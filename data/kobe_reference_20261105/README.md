# 神戸港の保存済み参照値

実験では、ここに保存した平均間隔を読み込む。CSVを取得・同期・再集計したり、Excelを作成したりしない。

```text
取得日：2026-10-23〜2026-11-04（13日）
翌日予定の対象日：2026-10-24〜2026-11-05
対象船席：PC-14・PC-15(E)・PC-16・PC-17
翌日予定件数の合計：103件
1日平均予定件数：103 / 13 = 7.923076923076923
基準平均間隔：24 * 13 / 103 = 3.029126213592233時間
```

各取得日の最後の入港船予定表から、翌日の対象船席への予定だけを抽出した。同じCSV内では「コールサイン（空欄なら船名）＋予定日」が同じ行を1件と数えた。未取得日は0件として補わない。取得履歴の行数やExcelの蓄積行数を船数に使っていない。

| ファイル | 保管内容 |
| --- | --- |
| [kobe_reference.json](kobe_reference.json) | 集計方法・期間・平均間隔・参照原本13件の名前とSHA-256 |
| [kobe_daily_forecasts.csv](kobe_daily_forecasts.csv) | 日別の翌日予定件数 |
| [kobe_reference_rows.csv](kobe_reference_rows.csv) | 対象行・原本の行番号・集計への採否 |
| `source_csvs.zip` | 参照原本13件。ZIP内は`取得日/元ファイル名`。原本を公開しないためGit対象外 |

JSONとCSVの3ファイルは[既存主実験の参照記録](../../results/final_20261105/)と同じ内容をコピーして保管した。ZIP内の原本はJSONのハッシュと照合済み。JSON内の絶対パスは集計時の保存場所を記録したもので、実験ではそのパスを読まない。

作成済みExcelは`data/kobe_port/船舶動静_蓄積.xlsx`に保管し、更新しない。既存の実験結果も変更しない。

## 収集を再開するコードはこの研究フォルダに置かない

収集専用リポジトリは[ryusuke2003/kobe-port-collector](https://github.com/ryusuke2003/kobe-port-collector)、データ用ブランチは`codex/kobe-port-data`。ローカル整理時には収集専用リポジトリを変更せず、Mac側の定期Excel同期を一時停止した。

その後、ユーザーの追加指示により、収集ワークフローに日本時間2026年11月21日までの期限チェックを追加した。22日以降は新規収集を開始しない。ワークフロー権限は従来の`contents: write`のまま。リポジトリとCSV履歴は削除しない。

定期実行`edi`はExcel同期から「11月21日分の収集後にGitHub Actionsを削除」へ変更し、11月22日9時（日本時間）に1回だけ、21日分の正常収集・保存を確認してワークフロー1ファイルを削除する予定にした。この確認・削除にはMacとアプリの起動が必要だが、GitHub側の収集期限はMacの起動状態に依存しない。欠損・失敗があれば削除を強行せず報告する。Excel同期は再開せず、Excelへの転記は後日のユーザー指示時に行う。

2026-11-09の整理時、ローカルCSV103件はデータ用ブランチのコミット`347d5ee91d02538d2ba11067919d73d6973fe2dc`と内容が一致した。ローカルのCSV群と同期記録は削除し、必要な原本13件をZIPに残した。削除した収集・集計・Excel作成コードは、この研究リポジトリのコミット`86887de`以前にある。

11月21日以降にデータを見直す場合は、当日分の収集完了・欠けた日・取得失敗を確認してCSVを取得し、別の集計記録を作る。取得日を11月21日までとすると、翌日予定は11月22日分まで含む。今回の13日103件の記録や主実験を黙って上書きしない。

この値は入港予定の規模の参考であり、実績寄港数・実際の到着分布・荷役時間・待ち時間を推定したものではない。
