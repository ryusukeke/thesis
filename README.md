# 到着予定情報の改ざんとバース運用

船は元の実到着時刻で来る一方、港側が偽の申告を信じて全船計画を更新する状況を調べます。全船の申告を船ごとに−8・−4・−2・＋2・＋4・＋8時間から独立に等確率で変更し、固定・同じバース内調整・バース変更の3方式を比較します。実到着とバース別荷役時間は正常時と共通です。

現在のモデルは`discrete_4berth_all_ships_random_v8`。既定10試行、1試行168時間、離散型4バースです。同じ試行の入力・改ざん内容を3方式で共有します。結果と考察は現行条件へ置き換え、過去のコピーは保存しません。

## 実行

Python 3.10以上と`requirements.txt`のライブラリを使います。既存のExcel出力処理にはopenpyxlを使用します。

```bash
.venv/bin/python -m pip install -r requirements.txt

# 全船ランダム改ざん・10試行を再現（空の保存先を指定）
.venv/bin/python main.py --output /tmp/thesis_reproduction

# 少数試行の動作確認は既存結果と別の保存先へ
.venv/bin/python main.py --trials 1 --output /tmp/thesis_check

# 手計算・物理制約・再現性・Excel保存の確認
.venv/bin/python -m unittest -v
```

| 引数 | 扱い |
| --- | --- |
| `--trials` / `--seed` | 既定10試行、開始seed42。既定は42〜51で実行 |
| `--output` | 既定`results/`。直下にファイルがあれば上書きせず停止 |
| `--no-plot` / `--no-save` | 描画だけ省略／保存・描画・保存先作成を省略 |

すべての実行で同じ全船ランダム改ざんを使い、別の主実験モードは設けません。保存済み参照JSONから平均到着間隔`24×13÷103=3.029126213592233`時間を読みます。参照JSONがなければ停止し、別の値へ切り替えません。船の多さ・対象割合・対象位置・単一方向・単一変更幅の比較ループはありません。

Excelは4シートとも日本語の見出し・方式・指標名とし、見出し固定・フィルターを付けます。「条件別集計」は上段の正常値・改ざん値・増減を読み、下段の詳細へ移動できます。増減の＋は悪化、−は改善です。「船別データ」は各試行・各船につき1行です。時刻は開始からの経過時間。隻数・シード・抽選した変更量など整数値は小数なし、小数値は有効数字3桁以内で不要な末尾0を省きます。保存値は丸めず、表示だけを整えます。Excelの編集では再シミュレーションされません。

「待ち理由」は、全バース使用中、指定バース使用中だが別バースは空き、計画順番待ち、計画開始待ちの4種類を記録します。この順で重複なく分類し、合計は元の待ち時間と一致します。競合はバース変更で、到着・完了時点に開始枠が不足した回数です。他2方式の競合欄は対象外で空欄とします。船別の競合参加回数は1つの競合に参加した各船へ数えるため、足しても運用全体の競合回数にはなりません。内訳は運用後の状態分類であり、各条件を取り除いた場合の改善量ではありません。

改ざん3方式×10試行＝30運用、正常3方式×10試行＝30運用、合計60運用です。異なる週の入力は10組で、正常と改ざんの結果を独立した標本とは数えません。各指標の試行平均・標本標準偏差、同じ試行・方式の正常との差、その最小・最大と増減回数を保存します。

## モデルと結果の扱い

到着間隔は指数分布、基準荷役時間はGamma(shape2, scale2.4)、平均4.8時間、最寄りバースは一様乱数という仮定です。バース別時間は基準×`(1+0.1×最寄りとの番号差)`。実港の分布や処理能力への当てはめではありません。

申告は`max(0, 実到着+抽選した変更量)`にします。開始前となる申告を0に丸めるため、一部の適用後の変更量は抽選した6値と異なります。全船を変更できる権限を攻撃者が持つ想定とし、100%・6値・等確率は実験上の設定です。混乱が最大になる攻撃だとは主張しません。

調整2方式は到着済みなら前倒し上限なし。全船が全バースを使え、荷役時間を正確に知り、調整に準備時間が要らない簡略化があります。実到着前の開始、荷役重複、開始後の中断・移動を認めません。全船が対象なので対象外群の集計は設けず、全体平均と悪化隻数・最大待ちを併せて確認します。今回の10試行から実港での効果や統計的有意差を断定しません。
