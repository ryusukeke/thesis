# 到着予定と実際のずれがバース運用に与える影響

港側が計画に使う到着予定時刻と、実際の到着時刻がずれた場合に、固定・同じバース内調整・バース変更の3方式で船の待ちがどう変わるかを調べます。予定が狂う要因には、天候や前の港での遅れ、情報の更新遅れ、入力ミスなどが考えられ、サイバー攻撃による情報改ざんもその一つとして位置付けます。

同じ実到着と荷役条件で、実到着順の10%地点にいる1隻の予定到着だけを2時間または8時間遅らせます。隻数×0.10を切り上げて対象を選ぶので、63隻なら実到着順の7隻目です。「ずれなし」は予定到着と実到着が一致する比較基準です。

到着頻度は基準の0.75・1・1.5倍です。基準の平均到着間隔を倍率で割って船を生成し、倍率ごとに1週間の実到着と荷役条件を3方式と両方のずれ幅で共有します。各条件を1試行（seed42）で実行します。予定ずれあり18運用とずれなし9運用の計27運用です。

## 実行

Python 3.10以上と`requirements.txt`のライブラリを使います。既存のExcel出力処理にはopenpyxlを使用します。

```bash
.venv/bin/python -m pip install -r requirements.txt

# 1隻の予定ずれ・各条件1試行を再現（空の保存先を指定）
.venv/bin/python main.py --output /tmp/thesis_reproduction

# 保存せず動作を確認
.venv/bin/python main.py --no-save

# 手計算・物理制約・再現性・Excel保存の確認
.venv/bin/python -m unittest -v
```

| 引数 | 扱い |
| --- | --- |
| `--trials` / `--seed` | 既定は各条件1試行、seed42 |
| `--output` | 既定`results/`。直下にファイルがあれば上書きせず停止 |
| `--no-plot` / `--no-save` | 描画だけ省略／保存・描画・保存先作成を省略 |

基準の平均到着間隔は保存済み参照JSONの約3.029時間です。0.75、1、1.5倍での平均間隔は約4.039、3.029、2.019時間です。1週間の隻数は到着の抽選結果で決まります。

## モデルと結果の扱い

到着間隔は指数分布、基準荷役時間はGamma(shape2, scale2.4)、平均4.8時間、最寄りバースは一様乱数という仮定です。バース別時間は基準×`(1+0.1×最寄りとの番号差)`。実港の分布や処理能力への当てはめではありません。

対象船の予定到着は実到着に2時間または8時間を加えます。残る船の予定到着は実到着と同じです。実験の2・8時間は比較用の設定です。

調整2方式は到着済みなら前倒し上限なし。全船が全バースを使え、荷役時間を正確に知り、調整に準備時間が要らない簡略化があります。実到着前の開始、荷役重複、開始後の中断・移動を認めません。全体平均、対象船の待ち、悪化隻数、最大待ちを併せて確認します。結果はseed42の入力に対する事例比較です。
