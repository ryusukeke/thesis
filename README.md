# 到着予定と実際のずれがバース運用に与える影響

港側が計画に使う到着予定時刻と、実際の到着時刻がずれた場合に、固定・同じバース内調整・バース変更の3方式で船の待ちがどう変わるかを調べます。予定が狂う要因には、天候や前の港での遅れ、情報の更新遅れ、入力ミスなどが考えられ、サイバー攻撃による情報改ざんもその一つとして位置付けます。

到着候補で最初の荷役計画を作り、各船の実到着と予定到着を荷役開始予定に合わせます。この計画は遅れ0時間の初期計画として保存します。以降はこの実到着と荷役条件を共通にし、調整後の実到着順で隻数×0.10を切り上げた順位の1隻だけ、予定到着を2時間または8時間遅らせます。

到着頻度は基準の0.75・1・1.5倍です。到着候補の基準平均間隔を倍率で割り、1週間分の到着候補を生成します。倍率ごとに調整後の実到着と荷役条件を3方式と両方のずれ幅で共有します。各条件を1試行（seed42）で実行します。実行するのは予定ずれありの18運用です。

## 実行

Python 3.10以上と`requirements.txt`のライブラリを使います。既存のExcel出力処理にはopenpyxlを使用します。

```bash
.venv/bin/python -m pip install -r requirements.txt

# 1隻の予定ずれ・各条件1試行を再現（空の保存先を指定）
.venv/bin/python main.py --output /tmp/thesis_reproduction

# 保存せず動作を確認
.venv/bin/python main.py --no-save

# 手計算・物理制約・再現性・Excel保存の確認
.venv/bin/python -m unittest -v
```

| 引数 | 扱い |
| --- | --- |
| `--trials` / `--seed` | 既定は各条件1試行、seed42 |
| `--output` | 既定`results/`。直下にファイルがあれば上書きせず停止 |
| `--no-plot` / `--no-save` | 描画だけ省略／保存・描画・保存先作成を省略 |

到着候補の基準平均間隔は `main.py` に記載した固定値の3.186時間です。神戸港EDIの30日分の翌日予定226件を基にしています。0.75、1、1.5倍での平均間隔は約4.248、3.186、2.124時間です。1週間の到着候補で船を選び、調整後の実到着が168時間以降の船も処理します。

図2・3・4は、それぞれ到着頻度0.75倍・1倍・1.5倍で、予定を8時間遅らせた実行例です。いずれもseed42です。最上段は予定の遅れを反映して組み直した計画です。各方式でその計画からバース・荷役開始・荷役完了のいずれかがずれた船を赤で示します。Excelでは各運用の船の待ち時間を合計します。複数試行を指定した場合は、試行ごとの合計を平均します。セルには元の数値を保存し、整数は小数点以下なし、小数は有効数字3桁以内で表示します。

「待ち理由」は、全バース使用中、指定バース使用中だが別バースは空き、計画順番待ち、計画開始待ちの4種類を記録します。この順で重複なく分類し、合計は元の待ち時間と一致します。競合はバース変更で、到着・完了時点に開始枠が不足した回数です。他2方式の競合欄は対象外で空欄とします。船別の競合参加回数は1つの競合に参加した各船へ数えるため、足しても運用全体の競合回数にはなりません。内訳は運用後の状態分類であり、各条件を取り除いた場合の改善量ではありません。

## モデルと結果の扱い

到着候補の間隔は指数分布、基準荷役時間はGamma(shape2, scale2.4)、平均4.8時間、最寄りバースは一様乱数という仮定です。バース別時間は基準×`(1+0.1×最寄りとの番号差)`。実港の分布や処理能力への当てはめではありません。

総待ち時間は実到着から荷役開始までを全船分足した値です。到着候補から実到着までの調整時間は「船別データ」に別途記録します。対象船の予定到着は実到着に2時間または8時間を加えます。残る船の予定到着は実到着と同じです。実験の2・8時間は比較用の設定です。

調整2方式は到着済みなら前倒し上限なし。全船が全バースを使え、荷役時間を正確に知り、調整に準備時間が要らない簡略化があります。実到着前の開始、荷役重複、開始後の中断・移動を認めません。全船の総待ち時間、対象船の待ち、待ちが生じた隻数、最大待ちを併せて確認します。結果はseed42の入力に対する事例比較です。
