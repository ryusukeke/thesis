# 到着時刻の改ざんとバース割当の予備比較

7月28日のゼミ報告にある、9月後半までの「正常時と攻撃時の予備比較」を行うプログラムです。
既存のFCFS割当を活かし、Pythonの関数と繰り返し処理で実装しています。
実験結果と考察の入口は [docs/予備比較レポート.md](docs/予備比較レポート.md) にまとめました。
変更前後の違いと修正理由は [docs/変更履歴.md](docs/変更履歴.md) にまとめました。
現実装から逆算した要件と、意図とのずれを確認する項目は [docs/要件定義書.md](docs/要件定義書.md) にまとめました。
`simulation.py` の計算処理は [docs/シミュレーション実装説明.md](docs/シミュレーション実装説明.md)、実行・出力処理は [docs/実験実行と出力の実装説明.md](docs/実験実行と出力の実装説明.md) に説明しています。

| ファイル | 役割 |
| --- | --- |
| `simulation.py` | 船舶データ生成、改ざん、バース割当、評価、比較実験の計算。結果を表として返す |

実行するファイルは `run_experiment.py` です。`simulation.py` は計算用の関数を定義し、直接実行しても実験や保存を開始しません。

## 実行方法

Python 3.10以上を使用します。すでに `.venv` があれば、そのまま使えます。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_experiment.py
```

初期設定は船10隻、バース3つ、V5の申告時刻を±4時間変更、100回実行です。
試行1はseed 42、試行2は43、というように141まで変更します。
それぞれの試行内では、3条件で船舶データと全バースの荷役時間を共有します。

設定を変更する例：

```bash
# 1回だけ実行して割当の詳細を見る
python run_experiment.py --trials 1 --output results_single

# 対象船と改ざん幅を変えて、別フォルダへ保存する
python run_experiment.py --attack-ship V7 --shift 2 --output results_v7

# 船数・バース数を変える
python run_experiment.py --ships 20 --berths 2 --output results_busy

# グラフが不要な場合
python run_experiment.py --no-plot
```

`--output` に同じフォルダを指定すると、そのフォルダの同名の結果ファイルを上書きします。
`--no-plot` の場合は、前回のグラフが残っていれば削除します。
今回の100回の結果を残して設定を変える場合は、別の保存先を指定してください。

## モデルの考え方

### 1. 荷役時間を作る

到着間隔は平均2.37時間の指数分布とします。
船ごとに基準荷役時間を `Gamma(shape=2, scale=2.4)` で生成します。
形状パラメータが整数のガンマ分布はErlang分布なので、これは2-Erlang分布です。
基準荷役時間の平均は4.8時間です。

各バースの荷役時間は、次の式で求めます。

```text
荷役時間 = 船ごとの基準荷役時間 × バース係数 × (1 + 小さな誤差)
```

3バースの係数は0.9、1.0、1.1、誤差は−0.05から+0.05の一様乱数です。
同じ船の基準時間を共有するので、荷役に時間がかかる船はどのバースでも比較的長くなります。
2バース以上では係数を0.9〜1.1に等間隔で置き、1バースなら1.0とします。
これらの値は予備実験用の仮定です。

### 2. 申告時刻で割当計画を作る

FCFS（First Come, First Served）は、先に到着すると申告された船から割り当てる方法です。
同じ申告時刻なら元の船番号順を使います。
各船について「荷役を最も早く開始できるバース」を選びます。
開始時刻が同じなら完了時刻、さらに同じならバース番号が小さい方を選びます。
割当計画は申告時刻だけを参照し、実到着時刻を使って補正しません。

### 3. 実際の到着に合わせて計画を実行する

改ざんされるのは船がシステムに伝える申告時刻で、船が実際に到着する時刻は変えません。
計画を作った後は、割り当てたバースと各バース内の順番を固定します。

```text
実荷役開始 = max(計画開始時刻, 実到着時刻, そのバースの直前の船の実完了時刻)
実完了時刻 = 実荷役開始 + 荷役時間
待ち時間 = 実荷役開始 − 実到着時刻
在港時間 = 実完了時刻 − 実到着時刻
```

早く申告した船がまだ来ていなければ、そのバースは予定の船が来るまで待ちます。
後続船が空き時間を使う再割当は行いません。
遅く申告した船は実際には到着済みでも計画開始まで待つ場合があります。
これは「誤った時刻を信じた予約計画を、そのまま実行する」という簡単なモデルです。
実港で随時再割当する運用への当てはまりは、別に検討する必要があります。

早い申告が0未満になる場合は0に丸めます。実際に変更した幅は `arrival_shift` に記録します。
待ち時間・在港時間は両条件とも実到着時刻から測り、同じ船番号で正常時との差を取ります。

## 保存するファイル

| ファイル | 内容 |
| --- | --- |
| `results/ship_data.csv` | 各試行の元データ。船番号、実到着時刻、基準荷役時間、全バースの荷役時間、seed |
| `results/schedules.csv` | 全試行・全条件の船別結果。実時刻・申告時刻、割当順・バース、計画と実行時刻、待ち時間・在港時間、正常時との差 |
| `results/run_metrics.csv` | 各試行・条件の総待ち時間、平均待ち時間、最大待ち時間、在港時間、全船の完了時刻、対象船とそれ以外の待ち時間 |
| `results/summary.csv` | 各条件・指標の平均と標本標準偏差 |
| `results/paired_comparison.csv` | 同じ試行の正常時との差、その平均・標準偏差・最小・最大、増加・減少・変化なしの回数 |
| `results/config.json` | 船数、バース数、改ざん条件、分布パラメータ、seed、実行方式、ライブラリのバージョン |
| `results/waiting_time_comparison.png` | 全船と対象船以外の平均待ち時間を比べるグラフ |

CSVはExcelで開きやすいUTF-8 BOM付きです。時刻・時間の単位はすべて時間です。
`normal` は正常時、`early` は早く申告する攻撃、`late` は遅く申告する攻撃です。
`waiting_time_change` などの差は「攻撃時 − 正常時」で、正の値が悪化を表します。
1試行だけの場合、標本標準偏差は定義できないのでCSVでは空欄です。
変化の回数は浮動小数点の誤差を避けるため、±0.000000001時間以内を「変化なし」とします。

## 確認方法

```bash
python -m unittest -v
```

手計算できる小さな例に加え、入力データの保持、実到着前に荷役しないこと、同じバースで重複しないこと、改ざん幅0で正常時と一致することを確認します。

## 神戸港の公開資料と仮定の区別

2026年10月6日に、神戸市の[神戸港の統計（年報）](https://www.city.kobe.lg.jp/a49918/tokei/annualreports.html)を確認しました。
入港隻数、貨物量、コンテナ個数、港湾施設などの集計が掲載されています。
[2024年の港湾統計の速報資料](https://www.city.kobe.lg.jp/documents/58977/2024kousei.pdf)では、外内貿コンテナ取扱個数は約277万TEUとされています。
この速報値は港全体の集計であり、今回の10隻・3バースのモデルを直接表す値ではありません。

確認した資料からは個別船の荷役開始・終了時刻の組を得ていません。
そのため、平均到着間隔2.37時間、平均基準荷役時間4.8時間、バース係数、誤差幅、攻撃幅は実測から推定した値として扱いません。
この実験は仮定した条件下で改ざんの影響を調べるためのものです。

分布の実装は [NumPyの `Generator.gamma` の説明](https://numpy.org/doc/stable/reference/random/generated/numpy.random.Generator.gamma.html)、Erlang分布との関係は [SciPyのErlang分布の説明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.erlang.html)を参照しています。
