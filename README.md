# 到着予定情報の改ざんとバース運用

2026年11月11日、実到着を計画に合わせない1隻版へ変更し、各条件100試行の主実験を実行しました。正常時にも待ちを認め、同じ方式・同じ入力の正常時からの増減を比較します。複数船の同時改ざんは次の段階です。[要件](docs/要件定義書.md)と[今後の計画](docs/今後の計画.md)を参照してください。

1隻の申告到着時刻だけが改ざんされたとき、他船へ待ちが広がる条件と、計画変更の許容範囲による軽減効果・限界を比較する学部卒論の研究コードです。離散型4バース、実到着を固定し、関数と繰り返し処理で計算します。

固定・同じバース内調整・バース変更の3方式を比較します。調整2方式には前倒し時間の上限がありません。今後の既定値も100試行とし、最新の図表・CSV・設定は`results/`直下に保存します。[結果・考察](docs/予備比較レポート.md)から執筆を始められます。これは仮定条件でのシミュレーションで、神戸港の実待ち時間による検証ではありません。

## 実行

既存の`.venv`を使用できます。新規環境ではPython 3.10以上で`requirements.txt`をインストールします。

```bash
# 神戸港の予定規模を使い、1週間分を1試行だけ保存せずに確認
.venv/bin/python main.py --trials 1 --no-save

# 主実験の再実行。既存結果とは別の保存先を指定する
.venv/bin/python main.py --study --output results/reproduction_20261111

# 手計算・物理制約・比較条件・保存済み参照値の確認
.venv/bin/python -m unittest -v

```

既定の保存先は`results/`直下です。直下にファイルがある場合は停止します。過去結果のサブフォルダだけなら保存できます。再実行時は現在の結果一式を過去結果フォルダへ移すか、新しい`--output`を使ってください。`--no-save`では保存先作成・保存・グラフ生成をしません。

通常の保存は`config.json`・`run_metrics.csv`・`summary.csv`とグラフに絞っています。参照記録は`data/kobe_reference_20261105/`にまとめ、結果フォルダへ再コピーしません。計画は運用の計算に使い、船別入力と運用結果は検証・描画用にメモリ内で保持します。正常との差は集計表にまとめ、重複する比較表や詳細CSVは作りません。コードの履歴はGitで管理し、結果フォルダへソースのコピーを残しません。

`config.json`には実験時のコード5ファイルと参照記録3ファイルのハッシュを記録します。保存済み100試行はコミット`2750b86`の計算コードによる結果で、その後の不要処理の整理で現コードのハッシュは変わっています。数値とグラフは整理前後で一致を確認しています。旧実験の検算手順は[過去資料](docs/過去資料/README.md#11月5日の旧実験を検算する)を参照してください。

| 引数 | 既定値・扱い |
| --- | --- |
| `--study` | 3方式の主実験全体を実行。省略時はV5・±4時間の単一設定 |
| `--trials` / `--seed` | 100試行、最初のseed42。試行ごとに1増やす（42〜141） |

## モデルと主実験

- 乱数で実到着と基準荷役時間を作り、荷物の最寄りバースを1〜4から一様に選びます。荷役時間は基準時間×`(1+0.1×バース番号の差の絶対値)`。基準時間はガンマ分布shape2、scale2.4で、平均4.8時間の仮定です。
- 正常申告を実到着と同じ時刻にして、重複しないバース計画を作ります。計画開始が遅くても実到着は動かさず、その差を正常時の待ちとして数えます。
- 改ざん後は実到着・荷役時間を動かさず、申告情報で全船の計画を1回更新します。同じ条件の計画は全方式で共通です。
- A固定、B同じバース内調整、Cバース変更を比較します。B・Cは前倒し上限なしで、到着済みの船を更新後の計画順で確認します。Cは最適解ではありません。
- 実到着の需要倍率0.75・1・1.5、対象位置10・50・90%、幅±2・4・8時間を、同じ100seedで比較します。300組の正常計画から改ざん16,200運用と正常900運用を実行します。同じ入力を条件間で共有するため、16,200個の独立した標本という意味ではありません。

生成する実到着の平均間隔は、KICT対象船席の各日最終CSVにある翌日予定を集計した`24×13÷103=3.029126…`時間を基準にします。予定件数であり、実績寄港数・実到着分布・荷役時間を推定した値ではありません。主実験には時間帯分布を直接入れず、到着間隔の分布形は指数分布という仮定を置きます。

## 保存結果

| ファイル | 読み方 |
| --- | --- |
| `config.json` | 数値条件、モデル版、seed、到着調整なしの明記・正常待ちの概要、コード・参照記録のハッシュ、資料URL |
| `run_metrics.csv` | 試行ごとの11指標。主実験100試行では正常参照値2,700行と攻撃16,200行 |
| `summary.csv` | 各条件の平均・標本標準偏差、正常平均、対応差の平均・標準偏差・増減回数。各セル100試行 |
| `01_…`〜`05_…`のPNG・PDF | 幅、需要、対象位置、正常と改ざんのスケジュール、正常待ちと増減の概要の5図 |

主実験は5図、通常の単一設定では図1（改ざん幅）と図5（概要）の2図を保存します。

CSVはUTF-8 BOM付きで、時間単位は時間です。`experiment_group`は主実験`main`のみ、`target_position`は到着順10%の`early`／50%の`middle`／90%の`late`です。`scenario`の`early`／`late`は申告を早める／遅らせる意味で、対象位置とは別の列です。

正常との差は、`run_metrics.csv`の同じ方式・需要・試行・対象位置の正常値を引いて求めます。`summary.csv`では`mean`が改ざん時の平均、`normal_mean`が正常平均、`mean_difference`が対応差、`mean_mitigation_vs_fixed`が固定方式の対応差からの軽減量です。差が負なら改善です。正常参照は改ざん幅ごとには複製しません。条件別の図1〜3は正常時からの増減の100試行平均、上側のひげは対応差の標本標準偏差1個分です。図5には正常・改ざん時の絶対値も示します。1試行の場合の標準偏差は未定義なのでCSVは空欄、図ではひげを描きません。有意差や信頼区間は示しません。

## 解釈の範囲

4バースは[商船三井の2026年8月19日の発表](https://www.mol.co.jp/info/article/2026/0819.html)を参考にしています。一方、全船が全バースを使えること、荷役時間が正確に分かること、前倒し上限なしは簡略化です。実到着は最初に生成した時刻から動かしません。船長・水深・クレーン・天候・実際の航行速度は計算しません。

Cでも正常時の待ちが発生するため、攻撃による増減は待ちそのものと分けて評価します。各方式は全体最適化ではありません。同じ情報ずれなら通常の誤報でも改ざんでも計算結果は同じです。[結論と限界](docs/予備比較レポート.md)を併せて読んでください。
