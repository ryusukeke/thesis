# 到着情報改ざんとバース運用の要件

更新日：2026年11月13日。全船ランダム改ざん・10試行・3方式の要件を記す。[結果](予備比較レポート.md)、[実装説明](実装説明.md)、[今後の計画](今後の計画.md)を参照する。

## 1. 研究の目的と対象範囲

全船が元の実到着で来る一方、港側だけが偽の申告を信じて計画を更新する状況を扱う。船ごとに申告の方向・変更幅が異なる状況で、正常時からの待ちの変化が運用方式によってどう異なるかを比較する。

攻撃想定は[先行研究の整理](../先行研究/先行研究の内容整理.md#到着情報改ざんの攻撃想定に使う資料)に対応付ける。ETA改ざんの脅威を参考にするが、同じ攻撃の実被害や本設定の発生確率を示す資料とは扱わない。侵入・検知・航行制御は計算しない。同じ誤情報なら通常の誤報でも計算結果は同じで、攻撃の意図を識別するモデルではない。

全船の申告を書き換えられる権限を攻撃者が持つ想定とする。全船・6種類の変更量・等確率は本研究の実験条件であり、先行研究から定まる値ではない。被害を最大化する探索は行わず、最悪攻撃とは説明しない。

## 2. 1試行の流れ

1. 168時間未満に来る全船の実到着・基準荷役時間・最寄りバースを生成する。
2. 正常申告を実到着と同じにし、正常計画を作って3方式で実行する。正常時にも待ちを認める。
3. 全船について、−8・−4・−2・＋2・＋4・＋8時間から独立に等確率で変更量を選ぶ。
4. 全船の申告を変更し、全船計画を運用開始前に1回更新する。
5. 全船は元の実到着で来る。同じ更新後計画を3方式で実行する。
6. 同じ試行・同じ方式の正常時との差を求め、10試行で集計する。

実到着と荷役開始は別である。実到着10時・開始12時なら2時間待つ。実到着・基準荷役・バース別荷役は変更しない。船側は港側の計画変更に合わせて航行を変えない。通常の予測誤差や追加の到着ずれは入れない。

計画作成は申告と既知と仮定したバース別荷役時間を使う。実行時は到着した事実と空き状況を使い、未来の実到着や比較用の正常計画から攻撃下の判断をしない。

## 3. 比較する3方式

表1 運用方式の規則

| 方式 | 実行時の規則 |
| --- | --- |
| 固定 | 計画バース・バース内順番を守り、計画開始前には始めない。実到着と前船の完了も待つ |
| 同じバース内調整 | 計画バースを維持。到着済み船を更新後の計画順で確認し、未到着船を飛ばして空き次第開始 |
| バース変更 | 同じ計画順で到着済み船を確認し、空きバースの中からその船の荷役時間が最短のものを選ぶ |

正常時は正常計画、改ざん時は更新後計画を使う。調整2方式とも前倒し上限なし。実到着順のFIFOへ切り替える規則ではない。実到着前開始・バース重複・二重処理は禁止し、開始後は中断・移動しない。別バースではそのバースの荷役時間を使う。後続船のために開始を止める先読みは行わない。

待ち0・改善・変化なしも結果として残す。待ちや方式差の発生を保証せず、結果による試行の選別はしない。

## 4. 入力と攻撃条件

表2 実験条件

| 項目 | 設定 |
| --- | --- |
| バース | 離散型B1〜B4。各バース同時1隻・各船同時1バース。全船が全バースを使用可能 |
| 到着生成期間 | 168時間未満。期間後の完了も含め全船処理 |
| 平均到着間隔 | 保存済み参照JSONの24×13÷103＝約3.029時間 |
| 到着間隔の分布 | 指数分布 |
| 基準荷役時間 | ガンマ分布shape2、scale2.4、平均4.8時間 |
| バース別時間 | 基準×(1+0.1×最寄りとの番号差)。最寄りは船ごとに一様乱数 |
| 改ざん対象 | 生成した全船。割合・位置で区分しない |
| 各船の変更量 | −8・−4・−2・＋2・＋4・＋8時間から独立に各1/6で抽選 |
| 改ざん後申告 | max(0, 実到着＋抽選した変更量) |
| 試行 | 10試行、seed42〜51が既定。到着はseed、属性はseed+100000、改ざんはseed+200000 |
| 初期状態 | 全バース空き。前後週からの継続流入なし |

到着・荷役・改ざんの乱数系列を分ける。変更量は元データの船の行順に1回抽選し、方式間で再抽選しない。早い・遅いの隻数や各変更幅の隻数を同数に固定せず、抽選結果をそのまま使う。抽選値と0未満を丸めた後の実際の変更量を区別して記録する。

正常3方式×10試行＋改ざん3方式×10試行＝60運用。異なる週の入力は10組である。需要倍率・対象割合・位置・方向・単一変更幅の比較ループは設けない。

分布・係数は仮定である。4バースと到着の規模は[保存済み参照記録](../data/kobe_reference_20261105/README.md)を参考にするが、実港の再現とは説明しない。参照値は自動更新せず、実験時の収集・同期・再集計は行わない。

## 5. 評価

主指標は全船平均待ちの正常差である。

```text
待ち時間 = 荷役開始 − 実到着
在港時間 = 荷役完了 − 実到着
改ざん影響 = 改ざん時の指標 − 同じ試行・方式の正常時の指標
```

総待ち・平均待ち・最大待ち、総在港・平均在港、最終荷役完了、計画からバースを変更した隻数、正常より待ちが増えた隻数の8指標を記録する。バース変更数は各条件の計画に対する変更で、正常計画との違いではない。

全船が対象なので対象外群は作らない。全体平均の正負の相殺を、最大待ちと船別の悪化隻数でも確認する。「待ちがある船」と「正常より待ちが増えた船」を区別し、後者は同じ船IDの待ちを引いて数える。

試行ごとの対応差を先に求め、平均・標本標準偏差・最小・最大・増減回数を集計する。±1e-9以内を変化なしとし、負の差を0に置換しない。1試行の標準偏差は未定義で空欄とする。実際の待ちと正常差を併記し、実港での効果や統計的有意差を断定しない。

## 6. 保存とグラフ

結果は`results/`直下に設定JSON、日本語Excel、3図のPNG/PDFを保存する。図タイトルは下、表タイトルは上。過去のアーカイブやソースコピーは作らない。

Excelは「条件別集計」「試行別結果」「船別データ」の3シート。上段は3方式の平均待ち比較、下段は8指標の詳細とする。船別データには各試行・各船1行で改ざん前の入力を保存し、抽選値・改ざん後申告・適用後変更量を追加する。試行・seed・乱数規則・参照データとコードのハッシュを記録する。

図1は正常／改ざん平均と各試行の対応差。図2・3は固定方式の平均待ち増分が最大の試行を説明用に選び、典型例とは説明しない。同値なら先の試行を選ぶ。集計には全試行を使う。週全体の影響を1件の改ざんの継続時間とは説明しない。

## 7. 検証

検証済みの内容は[結果レポート](予備比較レポート.md#7-検証と再現)を参照する。

- 正常計画を作っても実到着・荷役時間は不変。正常時にも待ちを認める。
- 手計算例（1バース、到着0・2・3、荷役各3）で開始0・3・6、待ち0・1・3を再現する。
- 全船の抽選値が6値に含まれ、seed+200000の等確率抽選と一致する。
- 同じ試行の3方式で改ざん後申告・入力を共有し、0未満の丸めも正しく記録する。
- 実到着前開始・荷役重複・二重処理を認めず、全船を完了まで処理する。
- 変更量0の確認用入力は正常運用と一致する。同じseedで再現する。
- 試行ごと・方式ごとの正常差と、Excelの保存値・数値書式・日本語表示が対応する。
- 一時保存先で確認後、現行の結果・設定・図・考察をそろえる。
