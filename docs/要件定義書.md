# 到着情報改ざんとバース運用の要件

更新日：2026年11月11日。実到着固定・複数船改ざんモデル（倍率比較なし・既定1試行・Excel保存）の要件を記す。結果は[比較レポート](予備比較レポート.md)、計算は[実装説明](実装説明.md)、今後の課題は[今後の計画](今後の計画.md)を参照する。

## 1. 研究の目的と対象範囲

船が元の到着予定どおりに来る一方、港側だけが改ざんされた到着申告を信じて計画を更新する状況を扱う。正常時から待ちがどれだけ増減するか、その影響が対象外の船へどう波及するかを、改ざんする隻数・割合を変えて3方式で比較する。

到着情報改ざんの想定は、Hacks・Pahl（2024）第4.2節のETA・ETD改ざんシナリオと、ENISA（2019）第4.3節Scenario CのPCSデータ改ざんの脅威整理を参考とする。[参照ページ・利用範囲](../先行研究/先行研究の内容整理.md#到着情報改ざんの攻撃想定に使う資料)にまとめる。実際の同一攻撃の被害事例とは説明しない。

対象は改ざんが受け入れられた後の運用への影響である。侵入手順、攻撃の発生確率、検知、防御技術、航行の制御は計算しない。同じ誤情報なら通常の誤報でも計算結果は同じで、意図の識別は行わない。新規性は未確認であり、既存の脅威と運用規則を用いた条件別の影響評価として位置づける。

## 2. 実到着と申告

最初に生成した実到着を、正常計画・申告変更・運用によって動かさない。正常申告は実到着と同じにし、対象船全隻の申告だけを変更する。実到着と荷役時間、他船の申告は変更しない。

実到着と荷役開始を区別する。例えば実到着10時、正常計画の開始12時なら、正常時にも2時間待つ。正常時の待ちが0の場合も正の場合も保持し、同じ入力・方式の正常時からの増減を評価する。

## 3. 1試行の計算の流れ

1. 期間内に実際に来る船の時刻、基準荷役時間、荷物の最寄りバースを生成する。
2. 正常申告を実到着と同じ時刻にし、全船の正常計画を作る。実到着は調整しない。
3. 正常計画を3方式で実行し、方式ごとの正常時の待ち・在港時間を記録する。
4. 選んだ対象群の申告を全隻変更する。主実験は全隻を早める／遅らせる条件、補足は早い・遅い申告の混在とする。
5. 変更後の申告に基づき全船計画を運用前に1回作り直す。その計画を3方式で共有する。
6. 全船は最初に決めた実到着で来る。各方式で実行し、同じ方式の正常時との差を計算する。

船側は港側の計画変更に合わせて到着を動かさない。

運用者が計画に使うのは申告と既知と仮定したバース別荷役時間である。実行時は到着した事実と空き状況を使い、未来の実到着や比較用の正常計画から判断しない。実験上は正常申告が実到着に一致すると置く。通常の予測誤差や、追加の到着ずれの乱数は今回追加しない。

## 4. 比較する3方式

| 方式 | 実行時の規則 |
| --- | --- |
| 固定 | その条件の計画バース・バース内順番を守る。計画開始より前には始めない。前の船が未到着なら待つ |
| 同じバース内調整 | 計画バースを維持する。到着済みの船をその条件の計画順で確認し、未到着船を飛ばし、使えるバースが空き次第始める |
| バース変更 | 到着済みの船をその条件の計画順で確認する。空きバースの中から、その船の荷役時間が最も短いものを選ぶ |

正常運用では正常計画、改ざん運用では更新後計画を参照する。調整2方式は全船に適用し、前倒し時間に上限を設けない。実到着順のFIFOへ切り替える規則ではない。

全方式で、実到着前の開始、同じバースの荷役重複、船の二重処理を禁止する。開始後は中断・移動しない。別バースを選んだ場合は、そのバースの荷役時間を使う。後続船への影響を先読みして開始を止める処理は追加しない。

バース変更の待ちが正になることや、改ざんで必ず悪化することは要件にしない。待ち0・改善・変化なしも結果として残し、見たい結果になるよう試行を選別しない。

## 5. 複数船版の実験条件

以下の分布・係数は研究上の仮定であり、神戸港の実測への当てはめではない。

| 項目 | 設定 |
| --- | --- |
| バース | 離散型B1〜B4。各バース同時1隻、各船同時1バース。全船が全バースを使用可能 |
| 到着の生成期間 | 168時間未満。期間後まで荷役が続く船も全船処理 |
| 基準平均到着間隔 | 保存済み参照JSONの24×13÷103＝約3.029時間 |
| 到着間隔 | 指数分布 |
| 基準荷役時間 | ガンマ分布shape=2、scale=2.4、平均4.8時間 |
| バース別荷役時間 | 基準時間×(1+0.1×最寄りバースとの番号差)。最寄りは船ごとに一様乱数で選ぶ |
| 改ざんの規模 | 1隻・全船の10%・30%・50%。割合から隻数は切上げ |
| 対象の選択 | 別乱数の順列の先頭から選ぶ。小さい対象群を大きい群に含める。位置別には分けない |
| 申告を変える幅 | 2時間・4時間・8時間 |
| 方向 | 全対象を早める／遅らせる主実験と、10%・30%・50%の混在補足。0未満は0へ丸める |
| 試行 | 各条件1試行、seed42を既定とする |
| 初期状態 | 全バース空き。前後週からの継続流入は計算しない |

同じ試行では、正常・全改ざん条件・3方式で実到着とバース別荷役時間を共有する。対象選択は到着・荷役時間とは別の乱数で行い、結果から選ばない。混在は選択順に符号を交互に割り当て、最初の符号だけ乱数で決める。対象集合と既存対象の符号を幅・割合の比較で固定する。改ざんの指定幅と、0で丸めた後の実際の変更幅を区別する。

主実験は4規模×3幅×2方向×3方式＝72運用、混在補足は3割合×3幅×3方式＝27運用。合計99改ざん運用と正常3運用を計算する。船の多さは変えず、保存済み参照値の平均間隔を使う。各条件で同じ1週間の入力を共有し、99個の独立した週の標本とは扱わない。

4バースの施設数と基準の予定規模は[保存済み参照記録](../data/kobe_reference_20261105/README.md)を参考にする。参照原本13件の集計を自動更新せず、実験時に参照データのCSV収集・再集計・保管用Excel作成を行わない。シミュレーション結果は別のExcelへ保存する。神戸港の実運用の再現とは説明しない。

## 6. 評価するもの

待ち時間は実際の荷役開始−実到着、在港時間は荷役完了−実到着とする。次を各試行で求める。

| 見る範囲 | 主に使う指標 |
| --- | --- |
| 対象外の船 | 平均待ち、待ちが生じた隻数、最大待ち、正常より待ちが増えた隻数 |
| 改ざん対象群 | 対象船群の平均待ち |
| 全船 | 総待ち・平均待ち・最大待ち、在港時間、全船完了時刻、正常より待ちが増えた隻数 |
| 計画からの変更 | 実行時にバースを変更した隻数。各条件の計画を基準に数える |

主指標は全船の平均待ちの正常差とする。割合で対象外群の構成が変わるので、群別平均だけで規模を比較しない。正常値は各条件と同じ対象集合で計算する。群が空なら平均・最大を未定義、隻数を0とする。

```text
方式ごとの改ざん影響 = 改ざん時の指標 − 同じ方式の正常時の指標
固定方式に対する軽減量 = 固定方式の改ざん影響 − 各調整方式の改ざん影響
```

方式間では実際の待ち時間と改ざんによる増減量の両方を報告する。正常時の方式差を攻撃の被害と取り違えない。差が負の場合は改善として残し、0に丸めない。正常値が0の場合に増加率を計算しない。±1e-9時間以内を変化なしとする。

各条件1試行の同じ入力での差を確認する。試行間の標準偏差は未定義なので空欄とし、1試行の結果を乱数が変わった場合の一般的な傾向とは扱わない。

結果の考察では、空きがあっても計画開始を守るための待ちと、実際にバースが埋まっているための待ちを区別する。全体平均、群別平均、悪化ケース数を併せて評価し、平均差が小さいことから個別船への影響がないとは判断しない。規則と整合する解釈と、要因を個別に変えて検証した事実も区別する。

## 7. 保存とグラフ

図番号・タイトルは図の下、表番号・タイトルは表の上へ置く。図内のパネルを区別する見出しは上に残してよい。

結果は`results/`直下へ保存し、設定・結果表・図・考察を現行の実験条件にそろえる。実験アーカイブや変更履歴ファイルは作成しない。動作確認は一時保存先で行う。

通常保存は`config.json`、`results.xlsx`（「条件別集計」・「試行別結果」・「船別データ」の3シート）、PNG・PDFのグラフとする。「条件別集計」の上段は全船平均待ちの正常値・改ざん値・差を条件と方式ごとに比較する一覧とし、下段に全13指標の詳細を残す。モデル版・実到着固定・seed・対象選択順・混在の規則・実際の対象数と割合・対象ID・実際の変更量・参照データとコードのハッシュを記録する。正常時の待ちの概要を確認できるようにする。

比較図は、正常時と改ざん時の待ち、正常時からの増減、改ざん規模・幅・負担先による違いを示す。時刻別の待ち船数とスケジュール図は説明用の例とし、事後に選んだ例を平均的なケースと説明しない。ひげを使う場合は平均とばらつきのどちらを示すか明記する。

船別入力は実到着・正常申告・基準荷役時間・最寄りバース・バース別係数と荷役時間・試行とシードを、各試行につき船ごとに1行でExcelへ保存する。計画は運用の計算に使い、既定では図用1試行だけ船別運用を保持する。通常の詳細CSVやソースコードのコピーは保存しない。

## 8. 検証する条件

検証済みの範囲は[結果レポート](予備比較レポート.md#7-検証と再現)を参照する。

- 正常計画を作っても実到着・荷役時間が変わらない。
- 1バース、到着0・2・3時間、荷役各3時間の例で、正常運用の開始0・3・6時間、待ち0・1・3時間を再現できる。
- 正常時に待ちがあってもエラーにせず、待ちが0の試行も保持する。
- 改ざんで変わる入力は対象群の申告だけ。対象0隻、0未満の丸め、同じ1隻の指定との一致も確認する。
- 対象集合が重複なく包含され、対象数の切上げ、混在の符号と再現性を確認する。
- 同じ改ざん条件の計画を3方式で共有し、実到着前開始・荷役の重複・全船の保持・開始後の中断禁止を検査できる。
- 改ざん幅0では、各方式の改ざん時の全指標が同じ方式の正常時と一致する。
- 同じseedと条件で再現でき、正常との差が試行ごとに正しく対応する。
- 一時保存先で確認後、各条件1試行を実行し、設定・Excel・図の対応を確認できる。
