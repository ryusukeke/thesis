# 実装から逆算した要件定義書

更新日：2026年11月5日（離散型を維持し、到着調整済み・正常時の待ち0を実装）

## 1. この文書の位置づけ

現在のコードが何を計算し、どの仮定を置いているかを確認する文書である。実装を正解と決めたり、仮設定を研究上の採用事項とみなしたりはしない。教授の指摘、採用した方向、未決定事項は[今後の計画](今後の計画.md)にまとめる。

対象は[simulation.py](../simulation.py)、[main.py](../main.py)、[既存の自動テスト](../test_simulation.py)である。実行方法と出力一覧は[README](../README.md)、計算と保存・表示の内部処理は[実装説明](実装説明.md)を参照する。

計画の由来は、ユーザー提供のゼミ資料、会話での依頼・教授の指摘、従来の実装である。申告だけを変更する比較、運用前の計画更新、複数ルールの比較、到着調整済みの正常計画を基準にすることは相談で採用した。分布の具体値、距離係数、週の初期状態の研究上の妥当性は別途確認する。

`results/`と[予備比較レポート](予備比較レポート.md)は、追加前の固定計画100試行の記録である。新しい週単位・複数ルールの結果として扱わない。

## 2. 目的と対象範囲

船舶の申告到着時刻の改ざんが、バース割当、待ち時間、在港時間に与える影響を、同じ元データの正常時と比較する。固定計画と、到着状況に応じて調整するルールの違いも確認する。

利用者は卒論研究を行う学生で、PC上でPythonを実行し、CSVとグラフを見て結果を説明する。実港への接続、運航の制御、侵入手法、複数船の同時攻撃、運用途中の継続的な改ざんは対象に含めない。

船型・水深・クレーン数・故障・潮位・出港作業、抜港、全体最適化、機械学習による検知、実データからの分布推定、有意差検定も現在は扱わない。

## 3. 用語・時刻・初期状態

| 用語 | 意味 |
| --- | --- |
| 到着候補時刻 | 乱数で作る調整前の時刻。実航海の到着実績ではない |
| 到着調整時間 | 正常計画の荷役開始に合わせ、候補から後ろへずらした時間。港での待ちとは別 |
| 実到着時刻 | 調整済みの船が実際に到着する時刻。攻撃で変えない |
| 申告到着時刻 | 計画が参照する到着情報。攻撃で変える |
| 基準荷役時間 | 船ごとの荷役規模を表す時間。各バースの計算で共有する |
| FCFS | 申告到着時刻の早い船から計画する規則 |
| 初期計画 | その条件の運用開始前の全船の計画。各ルールで共有する |
| 待ち時間 | 実到着から実際の荷役開始まで |
| 在港時間 | 実到着から荷役完了まで。離岸・出港は含まない |
| 試行 | 1組の元データについて、正常・早い申告・遅い申告と指定ルールを比較する単位 |

単位は時間とし、実際の日付を扱わない。期間指定では開始時刻0から終了時刻未満に到着候補を持つ船を対象とする。調整後の実到着が期間末以降でも除外しない。V1も最初に生成した到着間隔の後に到着する。固定隻数指定では従来どおりV1を時刻0に置く。全バースは時刻0に空いている。

週単位の初期状態とV1の扱いは仮設定である。週開始前からの荷役は実装していない。船番号は実在船のIDではなく、試行内のV1、V2、…という識別子である。

## 4. モデルの前提

**バースの扱いは離散型（BAP-D）に決定した（2026年11月5日、ユーザー決定）。** バースをB1、B2、…という区切られた枠として数え、各バースは同時に1隻、各船は同時に1バースを使用する。船長・岸壁長・岸壁上の着岸位置は計算しない。現在の実装もこの方式であり、計算方法の変更ではなく研究上の採用を明確にした。バース数の具体値は別途決める。初期値3は引き続き暫定値とし、神戸港の岸壁延長からバース数を自動換算しない。

| ID | 現在の実装上の前提 | 採用状況・残る確認 |
| --- | --- | --- |
| M-01 | 全船の申告と、船・バースごとの荷役時間から運用前に計画を作る | 荷役時間を正確に知る簡略化を採用。実港の性質とは断定しない |
| M-02 | 計画は申告で決め、実到着は実行時に使う | 情報だけの改ざんとして維持 |
| M-03 | 固定、同じバース内の調整、他バースへの変更を比較できる | 3ルールの比較を採用。数値条件は別途決める |
| M-04 | 調整ルールは到着済みの船を計画順で選び、早期開始を許す | 3ルールを実装・比較。実到着で動くルールの限界も明示する |
| M-05 | 1隻の申告を変え、全船の計画を運用前に1回更新する | 採用済み。運用中に全計画を繰り返し作り直さない |
| M-06 | 荷役は基準時間×係数で決まり、計画と実行で同じ時間を使う | noiseなしを維持。距離係数への変更は未実装 |
| M-07 | 全船が全バースを使える | 船型などの制約を省略した前提 |
| M-08 | 離散型のバース割当。各バースは同時に1隻、各船は同時に1バースを使用する | 2026年11月5日に採用決定。船長・岸壁長による配置は扱わない。バース数の具体値は未決定 |
| M-09 | 到着候補から予約を作り、実到着・正常申告を予約開始に合わせる。正常時は3ルールとも全船の待ち0 | 2026年11月5日採用。調整上限・速度・燃料は扱わず、現実の一般的性質とは断定しない |

未来の実到着をバース選択へ使わない。シミュレーションの時計を次の到着へ進める処理と、運用者が未来を知って判断する処理を区別する。

## 5. 機能要件

### FR-01：期間または固定隻数の元データ生成

期間指定では指数分布の間隔を順に足し、期間内の到着候補を作る。固定隻数では指定数の候補を作る。平均到着間隔は指定可能で、初期値2.37時間は仮定した暫定値とする。

基準荷役時間はshape=2、scale=2.4のガンマ分布で、平均4.8時間となる。複数バースの係数は0.9〜1.1の等間隔、1バースは1.0とし、船ごとに並べ替える。基準時間・係数配置・バース別荷役時間を元データへ記録する。同じ試行の全比較で値を共有し、noiseを加えない。

生成後に`create_normal_plan()`で候補から重複しないバース利用予定を作り、その荷役開始を実到着・正常申告とする。候補、調整時間、調整済みの時刻を保存する。調整は攻撃前に1回だけで、バース・順番・予約開始・完了は保持する。調整上限を設けず、速度・航行距離・燃料は計算しない。船ごとの基準荷役時間とバース係数は変更しない。

正常時の待ち0は、事前調整済みという研究仮定により構成する。到着候補の分布が、そのまま実到着の分布になるわけではない。現実の港の計画で必ず待ち0になると主張しない。

### FR-02：正常と1隻の早い・遅い申告

正常の申告は実到着と一致させる。攻撃は実到着に同じ幅を加減し、0未満は0へ丸める。実到着、荷役時間、他船の申告、元データは保持する。実際の変更幅も保存する。

実験プログラムの対象はV5固定で、対象指定のコマンド引数は設けない。計算関数は対象を引数で受け取る。生成された試行に対象がなければ、条件を見直すエラーとし、試行を再生成・除外しない。

### FR-03：全船の計画を各条件で1回作成

申告順で割り当て、同時刻なら生成データの船番号順を維持する。バースは計画開始が早い順、同じなら計画完了が早い順、さらに同じなら番号が小さい順で選ぶ。

```text
計画開始 = max(申告到着, バースの計画上の利用可能時刻)
計画完了 = 計画開始 + その船・バースの荷役時間
```

正常計画は到着調整時に作った予約を保存して使う。攻撃条件では改ざんした申告で全船の計画を作り直す。変更幅0や0への丸めで申告が変わらない場合も、同じ正常予約を使う。その条件の計画を全ルールが共有する。

### FR-04：物理的制約を守る3つの運用ルール

| ルール | 船とバースの選び方 | 計画開始より早い開始 |
| --- | --- | --- |
| `fixed` | 計画バースと、そのバースの順番を維持。未到着船を飛ばさない | 許さない |
| `same_berth` | 計画バースの到着済み・未開始の船を計画順で選ぶ。未到着船を飛ばす | 許す |
| `reassign` | 全到着済み・未開始の船を計画順で選び、空きバースを変更先にできる | 許す |

バース変更では、その船に対して荷役時間が最短の空きバースを選ぶ。同じなら番号が小さい順。複数の船は計画順で1隻ずつ選び、全組合せの最適化をしない。

同時刻の到着と完了をまとめて扱う。実到着前に開始せず、同じ船の二重処理と同じバースでの重複を認めない。荷役中の船を移動・中断しない。変更先に対応する荷役時間を使う。

到着調整で実到着が期間末以降となった場合も、期間終了後に全対象船の荷役を完了する。申告が期間外となった船も元の対象集合に含める。

### FR-05：同じ入力で試行・条件・ルールを比較

試行ごとにseedを1増やし、1回生成した元データを共有する。船別の比較は船番号、試行別の比較は試行番号で対応づける。攻撃時との差は同じルール自身の正常値から測る。

### FR-06：評価指標と正常条件の確認

待ち時間は実開始−実到着、在港時間は実完了−実到着とする。8指標は総・平均・最大待ち時間、総・平均在港時間、全船の完了時刻、対象船の待ち時間、他船の平均待ち時間とする。

試行別の隻数と、待ち時間が出た隻数も記録する。正常時は全ルール・全船の待ちが0であることを実行結果から検査し、1e-9時間を超えたらエラーにする。正常待ち時間を0へ置き換えたり、発生した試行を再生成・除外したりはしない。

### FR-07：平均、正常時との差、固定計画に対する軽減量

条件・ルール別に試行平均と標本標準偏差を集計する。同じルールの攻撃−正常について平均・標準偏差・最小・最大と増減回数を示す。±1e-9時間以内は変化なしとし、1試行の標準偏差はCSVで空欄にする。

固定計画と同時比較する場合は、固定計画の攻撃影響−各ルールの攻撃影響の平均を軽減量として保存する。正なら軽減となる。正常値が0を想定するため、まず時間差で評価し、正常値を分母にした増加率は使わない。

### FR-08：入力の検証

引数一覧と初期値は[READMEの実行方法](../README.md#実行方法)にまとめる。試行数1以上、バース数1以上、seed0以上、固定隻数2以上、有限で正の期間・到着間隔、有限で0以上の改ざん幅を要求する。指定ルールは既知の値で、重複を認めない。固定隻数と期間の同時指定を拒否する。

各試行で対象船が存在することを確認する。これらは通常の実験入口の検証であり、外部の任意の表についてすべての不正入力を検証する機能はない。

### FR-09・FR-10：保存・表示・グラフ

元データ、条件別の初期計画、条件・ルール別の実行結果、試行指標、集計、正常時との差のCSV6個と設定JSONを保存する。実行結果には計画バースと実行バースの両方を残す。

設定にはモデル識別子`coordinated_arrivals_v1`、到着調整方式・上限なし、候補時刻に適用する期間、試行別の調整時間合計・最終実到着・期間末以降の到着隻数、期間または固定隻数、試行別の実際の隻数、分布、seed、係数方式、対象、幅、ルール、初期状態、計画更新と同時イベントの規則、時間単位、NumPy・Pandasの版を記録する。

CSVはUTF-8 BOM付き。棒グラフは全船と他船の平均待ち時間を、条件とルールで比較する。値は試行平均で、誤差棒は付けない。日本語フォント依存を避けて英語表記とする。

初期保存先は`results_coordinated/`。旧モデルの`results/`と`results_new/`を既定で上書きしない。`--no-save`はすべての保存と既存グラフ削除を省略する。保存する場合、`--no-plot`でも古い同名PNGを削除して新しいCSVとの混在を避ける。同じ保存先は上書きなので条件ごとに保存先を分ける。

## 6. 構成・確認・残る課題

計算は`simulation.py`、引数・保存・表示は`main.py`に置く。関数と繰り返しを基本にし、クラス、イベント処理用の追加ライブラリ、最適化ソルバーを増やさない。

自動テスト18件は、固定計画、到着調整の手計算、3ルールの正常時0、情報だけの改ざんと他船への波及、別バースの荷役時間、再現性、期間末以降の対象保持、到着前の開始禁止・非重複、元データ・計画共有、係数、入力を確認する。出力は一時保存先でCSV・JSON・PNGを確認する。確認記録は[予備比較レポート](予備比較レポート.md)と[変更履歴](過去資料/変更履歴.md)へ記載する。

未実装・未確定の研究項目は、到着候補の間隔・バース数などの実験条件の根拠、荷物の位置と距離係数、対象位置を変えた一括比較、週開始前からの荷役などである。初期状態・分布・ルールの妥当性を、自動テストが証明するものではない。

今後も、実装した事項と採用した研究仮定を区別して文書を更新する。

## 7. 攻撃の想定（卒論用の案）

| 項目 | 定義案 |
| --- | --- |
| 攻撃目的 | 対象船以外の船の待ち時間を増やし、港湾運用を妨害する |
| 攻撃者が知る情報 | 対象船の到着予定時刻、船の識別子、割当が申告時刻順のFCFSで行われること |
| 攻撃者の能力 | 運用開始前の計画更新に使われる、1隻の到着予定時刻だけを書き換えられる |
| 改ざん内容 | 到着予定時刻を一定時間早める、または遅らせる |
| 変更しないもの | 実際の到着、荷役時間、他船の情報、バースの設備・能力 |
| 扱わないこと | システムへの侵入手法、運用途中の継続的な改ざん、複数船の同時攻撃 |

ここでの到着予定情報は、実装上の「申告到着時刻」に対応する。侵入経路は特定せず、その情報が書き換えられた後の運用への影響を模擬する。

### 計画更新と情報の使い方

運用者は改ざんを検知せず、申告情報の更新として受け入れる。正常な基準計画は研究者の比較用であり、攻撃条件の運用者が正しい時刻を復元するためには使わない。「元の計画」は、正常条件では正常な基準計画、攻撃条件では改ざん後に更新した計画を指す。各条件の計画をルール間で共有し、運用前の全船の計画更新と運用中の調整を区別する。

例えば、本来10時に到着予定の船の申告だけを6時へ変えても、実際の到着は10時のままである。この例は、攻撃者が将来の実到着を正確に知るという仮定ではない。計画作成と実行の規則は第5節、数式と具体例は[実装説明](実装説明.md)を参照する。

### 攻撃者が知らない情報

- 全船の正確な実到着時刻。
- 全船の正確な荷役時間。
- 改ざんした後に発生する待ち時間。

研究者が比較のために持つ情報と、攻撃者が使える情報を区別する。シミュレーション内部には実到着や荷役時間があるが、攻撃者が結果を先読みして最悪の対象を選べるという想定にはしない。
運用者は、船とバースの組合せごとの正確な荷役時間を事前に知っている前提を採用した。計画・再割当と実際の荷役には同じ値を使い、荷役時間の見積り誤差は扱わない。この前提は攻撃者に荷役時間を知らせるものではなく、運用者が未来の正確な実到着時刻を知るものでもない。

対象位置や改ざん幅を変える実験は、攻撃者の選択の最適化ではなく、条件による影響の違いを調べるものとする。対象位置・試行数などの今後の条件は[今後の計画](今後の計画.md)にまとめる。

対象船以外の平均待ち時間の正常時からの増加を主に確認し、全船と対象船自身の待ち時間も併記する。遅い申告で対象船自身だけが大きく待つ場合も報告し、すべての改ざんが攻撃目的を達成するとは仮定しない。同じ時刻のずれなら通常の予測誤差と改ざんで計算結果は同じになるため、意図的な書換えという想定と評価方法を明示する。

### 卒論に記載する文章案

研究全体は、既存のバース割当・再割当の考え方を限定した到着情報改ざんの攻撃モデルに適用し、被害と軽減の条件を評価するものと位置づける。詳しくは[今後の計画](今後の計画.md)の「研究の目的とゴール」を参照する。

> 本研究では、1週間のバース運用の開始前に、攻撃者が特定の1隻の到着予定時刻を書き換え、その情報で全船の計画が1回更新される状況を想定する。攻撃目的は、対象船以外の船舶の待ち時間を増加させる運用妨害とする。攻撃者は対象船の到着予定時刻とFCFSによる割当方式を知る一方、将来の正確な実到着時刻や荷役時間は知らないものとする。実際の船舶到着や荷役時間は変更せず、到着とバース利用が事前調整され、正常時に全船の待ち時間が0となる計画を基準に、改ざんの影響と複数の運用ルールによる軽減効果・限界を評価する。

正常時0は事前の到着調整を仮定した実装済みの条件であり、速度調整の実現可能性を検証したものではない。分布・係数・規模などの数値設定は引き続き仮設定である。実装済みの部分はこの文書の第3〜6節、保存済みの固定計画100試行と追加実装の動作確認は[予備比較レポート](予備比較レポート.md)を参照する。
