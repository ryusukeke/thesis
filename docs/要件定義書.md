# 到着情報改ざんとバース運用の改修要件

更新日：2026年11月11日。ユーザーが決定した研究の大筋を、実装前の要件として整理する。第1段階は到着調整をなくした1隻の改ざん、第2段階は複数船の同時改ざんとする。

**状態：新方針は採用済み、コードへの反映・再実験は未着手。** 現在のコード、`results/`直下の100試行、Wordは到着調整ありの旧モデルである。新方針の結果として扱わない。旧モデルの計算と結果は[旧結果のレポート](予備比較レポート.md)、現在のコードの説明は[実装説明](実装説明.md)、作業順序は[今後の計画](今後の計画.md)を参照する。

## 1. 研究の目的と対象範囲

船が元の到着予定どおりに来る一方、港側だけが改ざんされた到着申告を信じて計画を更新する状況を扱う。正常時から待ちがどれだけ増減するか、その影響が対象外の船へどう波及するかを3方式で比較する。まず1隻で仕組みを確認し、その後、改ざんする船の隻数または割合を増やす。

到着情報改ざんの想定は、Hacks・Pahl（2024）第4.2節のETA・ETD改ざんシナリオと、ENISA（2019）第4.3節Scenario CのPCSデータ改ざんの脅威整理を参考とする。[書誌情報・参照ページ・利用範囲](../先行研究/資料の入手元.md#到着情報改ざんの攻撃想定に使う資料)にまとめる。実際の同一攻撃の被害事例とは説明しない。

対象は改ざんが受け入れられた後の運用への影響である。侵入手順、攻撃の発生確率、検知、防御技術、航行の制御は計算しない。同じ誤情報なら通常の誤報でも計算結果は同じで、意図の識別は行わない。新規性は未確認であり、既存の脅威と運用規則を用いた条件別の影響評価として位置づける。

## 2. 今回変えること

| 項目 | 現在の旧モデル | 新しい要件 |
| --- | --- | --- |
| 実到着 | 正常計画の荷役開始へ合わせて延期 | 最初に生成した到着時刻をそのまま使う |
| 正常申告 | 到着調整後の実到着と同じ | 最初に生成した実到着と同じ |
| 正常時の待ち | 全船0を条件とし、0でなければ停止 | バースが埋まっていれば待つ。0も正の待ちも認める |
| 改ざんする値 | 対象船の申告到着時刻 | 同じ。実到着と荷役時間は動かさない |
| 主な比較 | 正常待ち0からの増加 | 同じ方式・同じ船データの正常時からの増減 |
| 改ざん対象 | 各条件1隻 | 第1段階は1隻、第2段階は複数船にも対応 |

実到着と荷役開始を区別する。例えば実到着10時、正常計画の開始12時なら、実到着を12時へ動かさず、正常時にも2時間待つ。

## 3. 1試行の計算の流れ

1. 期間内に実際に来る船の時刻、基準荷役時間、荷物の最寄りバースを生成する。
2. 正常申告を実到着と同じ時刻にし、全船の正常計画を作る。実到着は調整しない。
3. 正常計画を3方式で実行し、方式ごとの正常時の待ち・在港時間を記録する。
4. 選んだ船の申告だけを早い時刻または遅い時刻へ変更する。
5. 変更後の申告に基づき全船計画を運用前に1回作り直す。その計画を3方式で共有する。
6. 全船は最初に決めた実到着で来る。各方式で実行し、同じ方式の正常時との差を計算する。

複数船を扱う場合は、対象船全隻の申告を変更した後に計画を1回更新する。1隻ずつ運用と計画更新を繰り返す実験にはしない。船側は港側の計画変更に合わせて到着を動かさない。

運用者が計画に使うのは申告と既知と仮定したバース別荷役時間である。実行時は到着した事実と空き状況を使い、未来の実到着や比較用の正常計画から判断しない。実験上は正常申告が実到着に一致すると置く。通常の予測誤差や、追加の到着ずれの乱数は今回追加しない。

## 4. 比較する3方式

| 方式 | 実行時の規則 |
| --- | --- |
| 固定 | その条件の計画バース・バース内順番を守る。計画開始より前には始めない。前の船が未到着なら待つ |
| 同じバース内調整 | 計画バースを維持する。到着済みの船をその条件の計画順で確認し、未到着船を飛ばし、使えるバースが空き次第始める |
| バース変更 | 到着済みの船をその条件の計画順で確認する。空きバースの中から、その船の荷役時間が最も短いものを選ぶ |

正常運用では正常計画、改ざん運用では更新後計画を参照する。調整2方式は全船に適用し、前倒し時間に上限を設けない。実到着順のFIFOへ切り替える規則ではない。

全方式で、実到着前の開始、同じバースの荷役重複、船の二重処理を禁止する。開始後は中断・移動しない。別バースを選んだ場合は、そのバースの荷役時間を使う。後続船への影響を先読みして開始を止める処理は追加しない。

バース変更の待ちが正になることや、改ざんで必ず悪化することは要件にしない。待ち0・改善・変化なしも結果として残し、見たい結果になるよう試行を選別しない。

## 5. 第1段階で引き継ぐ実験条件

到着の調整をなくした影響を調べられるよう、既存の数値条件は引き継ぐ。以下の分布・係数は研究上の仮定であり、神戸港の実測への当てはめではない。

| 項目 | 設定 |
| --- | --- |
| バース | 離散型B1〜B4。各バース同時1隻、各船同時1バース。全船が全バースを使用可能 |
| 到着の生成期間 | 168時間未満。期間後まで荷役が続く船も全船処理 |
| 基準平均到着間隔 | 保存済み参照JSONの24×13÷103＝約3.029時間 |
| 船の多さ | 0.75倍・1倍・1.5倍。平均到着間隔は基準値÷倍率 |
| 到着間隔 | 指数分布 |
| 基準荷役時間 | ガンマ分布shape=2、scale=2.4、平均4.8時間 |
| バース別荷役時間 | 基準時間×(1+0.1×最寄りバースとの番号差)。最寄りは船ごとに一様乱数で選ぶ |
| 1隻の対象選択 | 実到着順の序盤10%・中盤50%・終盤90%。順位は端数切上げ |
| 申告を変える幅 | 2時間・4時間・8時間 |
| 方向 | 早い申告・遅い申告。変更後が0未満なら0へ丸める |
| 試行 | 各条件100試行、seed42〜141を既定とする |
| 初期状態 | 全バース空き。前後週からの継続流入は計算しない |

同じ需要・試行では、正常・全改ざん条件・3方式で実到着とバース別荷役時間を共有する。対象選択は生成した実到着順を基準とし、シミュレーション結果から選ばない。改ざんの指定幅と、0で丸めた後の実際の変更幅を区別する。

第1段階で全条件を引き継ぐ場合、改ざん運用は3需要×3対象位置×3幅×2方向×3方式×100試行＝16,200回、正常運用は3需要×100試行×3方式＝900回。正常運用は対象位置・幅ごとに実行し直さず共有する。繰り返し条件を独立標本数とみなさない。

4バースの施設数と基準の予定規模は[保存済み参照記録](../data/kobe_reference_20261105/README.md)を参考にする。参照原本13件の集計を自動更新せず、実験時にCSVの収集・再集計・Excel作成を行わない。神戸港の実運用の再現とは説明しない。

## 6. 評価するもの

待ち時間は実際の荷役開始−実到着、在港時間は荷役完了−実到着とする。次を各試行で求める。

| 見る範囲 | 主に使う指標 |
| --- | --- |
| 対象外の船 | 平均待ち、待ちが生じた隻数、最大待ち |
| 改ざん対象船 | 待ち時間。複数船では対象船全体の平均・合計を区別する |
| 全船 | 総待ち・平均待ち・最大待ち、在港時間、全船完了時刻 |
| 計画からの変更 | 実行時にバースを変更した隻数。各条件の計画を基準に数える |

主な被害指標は、対象外の船の平均待ちが正常時からどれだけ増減したかとする。港全体の影響は全船の総待ち・平均待ちなども併せて見る。

```text
方式ごとの改ざん影響 = 改ざん時の指標 − 同じ方式の正常時の指標
固定方式に対する軽減量 = 固定方式の改ざん影響 − 各調整方式の改ざん影響
```

方式間では実際の待ち時間と改ざんによる増減量の両方を報告する。正常時の方式差を攻撃の被害と取り違えない。差が負の場合は改善として残し、0に丸めない。正常値が0の場合に増加率を計算しない。±1e-9時間以内を変化なしとする。

条件ごとに100試行の平均・標本標準偏差と、同じ入力での差を確認する。対象外の船が0隻になる条件を設ける場合、その船群の指標は未定義として扱い、全船指標で評価する。

## 7. 第2段階で追加する機能と未決定条件

複数船の同時改ざん、実際の対象隻数・割合・船の識別子・各船の申告変更量の記録、改ざん対象と対象外の集計、隻数または割合による比較図を追加する。同じ条件の対象集合は3方式で共通にする。

以下はまだ決定していない。第1段階の実装には影響しない。

| 決める項目 | 初期案（採用前） |
| --- | --- |
| 対象範囲の水準 | 1隻を基準に、例えば全船の10%・30%・50%へ増やす。固定隻数で比較する案もある |
| 対象船の選び方 | 乱数で重複なく選び、seedと対象集合を記録する案 |
| 変更方向 | まず対象全船を早める条件と遅らせる条件を分け、混在条件は別途判断する案 |
| 時刻幅 | まず既存の2・4・8時間を共通の幅として使う案 |
| 割合から隻数への変換 | 端数の丸め、最小隻数、指定割合と実際の割合を明示する |

対象集合の全組合せを網羅することは要件にしない。対象の選び方や水準を増やした場合は、実行数を計算してから主実験を行う。第1段階と第2段階では対象選択が違う場合があるので、位置別の1隻実験と割合別の複数船実験を区別して報告する。

## 8. 保存とグラフ

最新結果は`results/`直下へ保存する。現在の旧結果は設定・CSV・図を一式で過去結果フォルダへ保管してから更新する。旧結果・新結果を同じモデル版として混ぜない。

通常保存は`config.json`、`run_metrics.csv`、`summary.csv`、PNG・PDFのグラフとする。モデル版・到着調整なし・seed・改ざん対象条件・参照データとコードのハッシュを記録する。到着調整時間など、廃止した処理の診断項目は新結果の設定・図から外す。正常時の待ちの概要を確認できるようにする。

比較図は、正常時と改ざん時の待ち、正常時からの増減、幅・需要・対象位置による違いを示す。第2段階では改ざん隻数・割合による違いも示す。スケジュール図は待ちの波及を説明するための例とし、事後に選んだ例を平均的なケースと説明しない。ひげを使う場合は平均とばらつきのどちらを示すか明記する。

船別入力・計画・運用は計算・図のために使うが、通常の詳細CSV保存は追加しない。ソースコードの記録用コピーも作らない。メモリ使用量を確認し、条件追加で重くなる場合は条件ごとの処理や集計後の詳細データ解放を検討する。

## 10. 第1段階の完了条件

- 正常計画を作っても実到着・荷役時間が変わらない。
- 1バース、到着0・2・3時間、荷役各3時間の例で、正常運用の開始0・3・6時間、待ち0・1・3時間を再現できる。
- 正常時に待ちがあってもエラーにせず、待ちが0の試行も保持する。
- 改ざんで変わる入力は対象船の申告だけ。0未満の丸めも確認できる。
- 同じ改ざん条件の計画を3方式で共有し、実到着前開始・荷役の重複・全船の保持・開始後の中断禁止を検査できる。
- 改ざん幅0では、各方式の改ざん時の全指標が同じ方式の正常時と一致する。
- 同じseedと条件で再現でき、正常との差が試行ごとに正しく対応する。
- 少数試行を一時保存先で確認後、本実験を各条件100試行で実行し、設定・CSV・図の対応を確認できる。
- 新結果が出てから考察を更新し、旧モデルの29.7%などの数値を引き継がない。

第2段階では、重複のない対象集合、指定した隻数・割合と実際の対象、変更対象外の申告の不変、対象0隻での正常一致、対象1隻での単一対象処理との一致、対象外0隻の場合の扱いも確認する。
