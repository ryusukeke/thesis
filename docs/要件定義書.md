# 到着予定と実際のずれを比較する要件

更新日：2026年11月25日。1隻の予定ずれ・各条件1試行・3方式の要件を記す。[結果](予備比較レポート.md)、[実装説明](実装説明.md)、[今後の計画](今後の計画.md)を参照する。

## 1. 研究の目的と対象範囲

港側が計画に使う予定到着時刻と実到着がずれた状況で、待ちの変化が運用方式によってどう異なるかを比較する。予定のずれは、天候や前の港での遅れ、情報更新の遅れ、入力ミスなどでも生じ得る。サイバー攻撃による到着情報の改ざんは、その要因の一つとして位置付ける。

本モデルでは原因別の過程を作り分けず、最初の荷役開始予定に合わせた実到着と荷役条件を全条件で共有し、予定ずれありでは計画に使う予定到着情報だけをずらす。「申告」は港側が受け取る予定到着情報、予定到着と実到着が一致する状態は、遅れ0時間の初期計画として保存する。予定到着−実到着が負なら実際より早い予定、正なら実際より遅い予定となる。船が航行中に遅れる過程や、天候・攻撃の発生確率を推定する実験ではない。

[関連資料](../先行研究/先行研究の内容整理.md#到着情報改ざんの攻撃想定に使う資料)のETA改ざんは、情報のずれを検討する背景の一つとして参照する。対象1隻・実到着順10%・2時間と8時間は比較のための仮定であり、特定の原因の実測分布ではない。侵入・検知・航行制御や、攻撃者による被害最大化は計算しない。

## 2. 1試行の流れ

1. 到着頻度0.75・1・1.5倍ごとに、168時間未満の到着候補・基準荷役時間・最寄りバースを生成する。
2. 到着候補で最初の荷役計画を作り、各船の予定到着と実到着をその荷役開始予定に合わせる。この計画を船別データに保存する。
3. 調整後の実到着順の `ceil(隻数×0.10)` 番目の1隻を選ぶ。同着なら入力順。
4. 同じ対象船の予定到着に2時間または8時間を加え、幅ごとに全船計画を運用前に1回更新する。
5. 更新後の計画を3方式で実行し、総待ち時間などを求める。

実到着と荷役開始は別である。実到着10時・開始12時なら2時間待つ。実到着の調整は最初に1回行う。予定ずれを加えた後の計画更新では、調整後の実到着・基準荷役・バース別荷役を共通の入力として使う。

更新する計画には申告と既知と仮定したバース別荷役時間を使う。実行時は到着した事実と空き状況を使い、実行時の判断は更新後の計画とその時点で得られる情報に基づく。

## 3. 比較する3方式

表1 運用方式の規則

| 方式 | 実行時の規則 |
| --- | --- |
| 固定 | 計画バース・バース内順番を守り、計画開始前には始めない。実到着と前船の完了も待つ |
| 同じバース内調整 | 計画バースを維持。到着済み船を更新後の計画順で確認し、未到着船を飛ばして空き次第開始 |
| バース変更 | 同じ計画順で到着済み船を確認し、空きバースの中からその船の荷役時間が最短のものを選ぶ |

2時間と8時間の運用は、それぞれ更新後の計画を使う。調整2方式とも前倒し上限なし。実到着順のFIFOへ切り替える規則ではない。実到着前開始・バース重複・二重処理は禁止し、開始後は中断・移動しない。別バースではそのバースの荷役時間を使う。後続船のために開始を止める先読みは行わない。

初期計画では到着と荷役開始の予定が一致する。2時間・8時間の運用で待ちが0のケースも集計に含める。

## 4. 入力と予定ずれの条件

表2 実験条件

| 項目 | 設定 |
| --- | --- |
| バース | 離散型B1〜B4。各バース同時1隻・各船同時1バース。全船が全バースを使用可能 |
| 到着候補の生成期間 | 168時間未満。調整後の到着や荷役完了が期間後の船も処理 |
| 到着候補の基準平均間隔 | 3.186時間（神戸港EDIの翌日予定から24×30÷226で求め、小数第3位に丸めた固定値） |
| 到着候補の間隔の分布 | 指数分布 |
| 基準荷役時間 | ガンマ分布shape2、scale2.4、平均4.8時間 |
| バース別時間 | 基準×(1+0.1×最寄りとの番号差)。最寄りは船ごとに一様乱数 |
| 到着頻度 | 基準の0.75・1・1.5倍。到着候補の平均間隔は基準値÷倍率 |
| 対象船 | 実到着順で隻数×0.10を切り上げた順位の1隻。62隻なら7隻目 |
| 予定の遅れ | 対象船の予定到着に2時間または8時間を加える |
| 試行 | 既定は各条件1試行、seed42。到着はseed、船の属性はseed+100000 |
| 初期状態 | 全バース空き。前後週からの継続流入なし |

到着と船の属性の乱数系列を分ける。対象船とずれ幅の決定には乱数を使わない。各試行・到着頻度の調整後の実到着と荷役条件を、2時間・8時間および3方式で共有する。

既定では3頻度×2幅×3方式の18運用を1回ずつ実行する。初期計画は到着頻度ごとに一つ作る。到着頻度間も同じ試行シードを使う。

分布・係数は仮定である。4バースと到着の規模は[保存済み参照記録](../data/kobe_reference_20261105/README.md)を参考にするが、実港の再現とは説明しない。実験はコードに記載した固定値で実行する。

## 5. 評価

主指標は各運用の全船の総待ち時間である。

```text
待ち時間 = 荷役開始 − 実到着
全船の総待ち時間 = 各船の待ち時間の合計
在港時間 = 荷役完了 − 実到着
```

到着候補から実到着までの調整時間は、実到着より前の調整として別に記録する。

総待ち・最大待ち、総在港・平均在港、最終荷役完了、計画からバースを変更した隻数、待ちが生じた隻数の7指標に対象船の待ちを加えた8指標を記録する。バース変更数は各条件の計画に対する変更で、ずれなしの計画との違いではない。

対象船自身の待ちも記録し、全船の総待ち時間への影響と合わせて読む。待ちが一部の船に集中していないか、最大待ちと待ちが生じた隻数も確認する。1e-9時間を超えて待った船を数える。

各指標の試行平均・標本標準偏差・最小・最大を集計する。1試行の標準偏差は空欄とする。実港での効果や統計的有意差を断定しない。

待ちの補助計測は、運用後の開始・完了時刻から行い、運用判断には使わない。各船の待ちを次の優先順で重複なく分類し、合計が待ち時間に一致するようにする。

表3 待ちの状態分類

| 優先順 | 記録する時間 | 条件 |
| --- | --- | --- |
| 1 | 全バース使用中 | 全バースが荷役中 |
| 2 | 指定バース使用中・別バース空き | 全バース使用中ではないが、その船の指定バースが荷役中 |
| 3 | 計画順番待ち | 固定方式で、指定バースは空きだが計画上の先行船が未完了 |
| 4 | 計画開始待ち | 固定方式で、先行船完了・指定バース空きでも計画開始前 |

複数条件が重なる時間は上位の区分に数える。これは時間帯の状態分類であり、原因ごとの独立した寄与量ではない。

バース変更の競合は、同時刻の到着・完了をまとめ、新たな荷役開始前に「到着済み待ち隻数＞空きバース数＞0」となった時刻を1回と数える。空き0の時刻は開始枠の選択ができないため数えない。船別には、その競合の全候補船へ参加1回を記録する。他2方式は計測対象外で空欄とする。

## 6. 保存とグラフ

結果は`results/`直下に設定JSON、日本語Excel、4図のPNGを保存する。図タイトルは下、表タイトルは上。過去のアーカイブやソースコピーは作らない。

Excelは「条件別集計」「試行別結果」「船別データ」「待ち理由」の4シート。上段は3方式の総待ち時間の比較、下段は8指標の詳細とする。船別データは各試行・到着頻度・船につき1行で、到着候補・調整後の実到着・調整時間・初期計画のバースと荷役予定・荷役条件・予定をずらす船の区分を保存する。ずらした予定到着時刻は「待ち理由」の運用別明細に載せる。試行・seed・乱数規則・平均到着間隔の根拠資料へのパスを記録する。

「待ち理由」の上段は到着頻度・遅れ幅・方式ごとの結果、下段は全試行・全運用の船別明細とする。入力の「船別データ」は各船1行のまま保持し、運用別の待ち明細と区別する。試行別結果には全船の総待ち時間の内訳と競合回数も保存する。

図1は到着頻度・予定の遅れ・方式別の全船の総待ち時間。図2・3・4はそれぞれ到着頻度0.75倍・1倍・1.5倍で、予定を8時間遅らせた実行例。複数試行を指定した場合は、各到着頻度で固定方式の全船の総待ち時間が最大の試行を使う。同値なら先の試行を選ぶ。集計には全試行を使う。週全体の結果を、一つの原因や1件の攻撃の継続時間・被害とは説明しない。

## 7. 検証

検証済みの内容は[結果レポート](予備比較レポート.md#5-保存と検証)を参照する。

- 手計算例（1バース、到着候補0・2・3、荷役各3）で調整後の実到着と荷役開始が0・3・6となり、ずれなしの待ちは全船0になる。
- 実到着順の10%地点の1隻だけを選び、その船の予定にだけ2時間または8時間を加える。
- 同じ試行・到着頻度の2幅と3方式で対象船、実到着、荷役条件を共有する。
- 実到着前開始・荷役重複・二重処理を認めず、全船を完了まで処理する。
- 遅れ0時間は初期計画に保存し、試行別結果と待ち理由には2時間と8時間の運用だけを載せる。同じseedで再現する。
- 各運用の指標とExcelの保存値・数値書式・日本語表示が対応する。
- 各船の待ち内訳が合計に一致し、同時刻の競合を重複計上しない。追加計測で元の入力・運用・指標が変わらない。
- 一時保存先で確認後、現行の結果・設定・図・考察をそろえる。
