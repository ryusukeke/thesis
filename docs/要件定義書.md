# 研究の前提と要件

更新日：2026年11月5日。ユーザーが採用した提案を、4バースで実装・実験した範囲を記す。実装は研究上の仮定を表し、実港での妥当性や卒論審査を自動的に保証しない。

## 1. 目的

到着とバース利用を事前調整した正常待ち0の状態から、1隻の申告時刻だけの改ざんが他船へ及ぼす影響と、計画変更の許容範囲による軽減の条件・限界を調べる。

研究の問いは、(1)影響が広がる条件、(2)同じバース内の調整とバース変更の違い、(3)前倒し制約が軽減効果へ及ぼす影響、の3点とする。新しい最適化手法、攻撃検知技術、実港の被害予測を目的にしない。

## 2. 用語と対象

| 項目 | 採用した前提 |
| --- | --- |
| 対象 | KICTの4バース体制を参考にした仮想コンテナターミナル |
| バース | 離散型B1〜B4。各バース同時1隻・各船同時1バース。全船が全バースを使用可能 |
| 空間 | 船長・岸壁長・岸壁上の連続位置を扱わない。番号差は仮想的な距離の段階 |
| 到着候補 | 正常計画の調整前に乱数で作る時刻 |
| 実到着 | 正常予約の開始に調整した到着。攻撃後は固定 |
| 申告到着 | 計画が参照する情報。対象船のこの値だけを改ざんする |
| 荷役 | 船ごとの基準時間×バース係数。計画・実行で同じ値を使う |
| 待ち時間 | 実開始−調整後の実到着 |
| 在港時間 | 荷役完了−調整後の実到着。出港・離岸は含まない |
| 期間 | 時刻0〜168未満の候補を対象にし、調整後の到着・完了が期間外でも全船を処理する |
| 初期状態 | 全バース空き。前週からの荷役と翌週の新規流入はない |

## 3. データ生成と正常計画

候補間隔は指数分布、基準荷役時間はガンマ分布shape2・scale2.4とする。荷役時間の平均4.8時間は仮定値であり、KICT実測値ではない。荷物の最寄りバースを1〜4から一様乱数で選び、係数を`1+0.1×|最寄り番号−使用バース番号|`とする。係数・最寄り位置・荷役時間は比較条件間で共有し、noiseを加えない。

到着候補の申告順で、開始が最も早いバース、同時なら完了が最も早いバース、さらに同時なら小さい番号を選ぶ。予約を作った後、各船の実到着と正常申告をその開始時刻に合わせる。候補と到着調整時間を保存し、予約のバース・順番・開始・完了は保持する。

正常時は4方式で実行し、全船の待ち0を検査する。1e-9時間を超えたらエラーで停止する。実行後の待ちを0へ置換せず、失敗試行の除外・再生成もしない。速度・燃料・到着調整上限は計算しない。

## 4. 神戸港データの参照範囲

`port_collection/analyze_port_data.py`は、各日の最終取得CSVにある翌日入港予定からPC-14・PC-15(E)・PC-16・PC-17だけを抽出する。同じ選択スナップショット内のコールサイン（なければ船名）と予定日が同じ行は1件とする。未取得日を0件と補わない。

取得日2026-10-23〜11-04の13スナップショットが、翌日10-24〜11-05の103予定船日を含む。これを到着候補の規模の参考とし、平均間隔を`24×13/103`時間にする。主実験はその発生率を0.75・1・1.5倍に変える。

これは「前日の最後に観測できた翌日予定件数」である。同じ実寄港の予定日変更や同日複数寄港は識別しきれず、実績寄港数ではない。時間帯分布、指数分布への適合、荷役時間、実待ち時間を推定したとは説明しない。施設数はCSVのコード数ではなく公式発表を根拠にする。

## 5. 攻撃と計画更新

運用前に選んだ1隻の申告時刻を±2・4・8時間変更する。0未満は0へ丸め、実際の変更幅を保存する。運用者は改ざんを検知せず申告更新として受け入れ、全船の計画を1回更新する。情報が変わらない幅0や丸めの場合は正常予約を維持する。

対象は到着順の10・50・90%の順位（端数切上げ）から各条件1隻を選ぶ。結果を先読みして最大被害の船を選ばない。単一設定の確認用CLIではV5を使う。

攻撃者が知るのは対象の識別子・到着予定とFCFS方式とし、全船の正確な将来の到着・荷役時間は知らない。侵入手法、複数船同時攻撃、途中で何度も書き換える攻撃は扱わない。

運用者はバース別の荷役時間を正確に知る仮定を置くが、未来の実到着は選択に使わない。正常計画は研究者の比較用であり、攻撃条件の運用者が時刻を復元する情報にはしない。

## 6. 運用ルール

| 方式 | バースと順番 | 前倒し |
| --- | --- | --- |
| A `fixed` | 更新後の計画バースとバース内順番を維持。未到着船を待つ | なし |
| B `same_berth` | 計画バースの到着済み・開始可能な船を計画順で選ぶ | 上限2時間 |
| C `reassign` | 到着済み・開始可能な船を計画順で選び、空きバース中で荷役最短を選ぶ | 上限2時間 |
| D `unrestricted` | Cと同じだが開始の前倒し制限を外す | 無制限 |

補足実験は中盤・±4時間のCについて上限0時間を計算し、主実験の2時間・Dと比較する。2時間は実測値ではなく仮定値であり、上限の違いへの依存を調べる。

B・Cの開始可能時刻は`max(実到着, その条件の更新後計画開始−上限)`。時計は到着・開始制限解除・荷役完了に合わせて進める。同時イベントをまとめ、同時の優先は入力の安定順とする。実到着前の開始、同一バースの荷役重複、船の二重処理、荷役中の移動・中断を認めない。別バースでは変更先の荷役時間を使う。

Dは理論最適解ではない。同時到着のない今回の入力では正常運用を再現して待ち0となる構造があり、完全防御や実港の効果とは解釈しない。

## 7. 比較・評価・保存

同じ需要倍率・seedで同じ正常データ・予約を全条件に使う。seed42〜51を各セル10試行とし、同じ方式・需要・試行・対象位置の正常値との差を測る。比較条件ごとの平均と標本標準偏差、増減回数を保存する。±1e-9時間以内を変化なしとする。0を分母にした増加率は使わない。

主指標は対象船以外の平均待ち時間。補助指標は他船の待ち隻数・最大待ち、対象船の待ち、全船の待ち・在港時間、完了時刻、実行時のバース変更隻数とする。バース変更はその条件の更新後計画を基準に数える。正常計画からの到着調整量も別に残す。

30正常計画から主実験2,160ケース、補足60ケースを計算する。正常参照値は対象位置ごとに残すが、正常計画の数を増やすものではない。需要間もseedと属性を共有するので、30組を相互に独立した標本とはみなさない。10試行や条件の繰返しを理由に統計的有意差を断定しない。

計算は`simulation.py`、実行の流れは`main.py`、引数の定義・読み取り・チェックは`cli.py`、設定・表の保存と概要表示は`result_output.py`、グラフは`plotting.py`に分ける（2026年11月9日に引数・出力処理を分離。モデルは変更なし）。出力一覧とコマンドは[README](../README.md)、内部処理は[実装説明](実装説明.md)、結果・検算は[レポート](予備比較レポート.md)を参照する。既存の結果・原本・Excelは更新しない。新しい保存先が非空なら停止する。

2026年11月9日から、4バース・168時間の候補生成期間・改ざん幅・前倒し上限・4方式の比較はコード内の実験条件として管理する。通常実行のV5・±4時間、主実験の3対象位置・±2/4/8時間は維持する。固定隻数・手動の平均間隔・参照場所・取得日上限もシミュレーションのCLIから外し、通常実行と主実験の両方で神戸港データから基準平均間隔を求める。参照場所とCSV取得日上限2026-11-04はmain.py内で固定する。通常実行の基準値は仮定の3.0時間から約3.029時間へ変わるため、以前の通常実行とは船数や結果が変わり得る。主実験の条件と保存済み結果は維持する。
