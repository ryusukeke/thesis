# simulation.py 全体の実装説明

作成日：2026年10月6日

更新日：2026年10月7日（計算・出力の分離と船ごとの係数の並べ替えを反映）

対象：[simulation.py](../simulation.py)

## 1. このプログラムで行うこと

このプログラムは、船の到着時刻の情報が改ざんされたとき、港のバース割当や待ち時間がどう変わるかを調べるシミュレーションである。
バースとは、船が接岸して荷物の積み下ろしを行う場所を指す。
ここでは、1つのバースで同時に荷役できる船は1隻とする。

まず船の到着時刻と荷役時間を乱数で作り、次の3条件を同じデータで比較する。

| 条件 | 内容 |
| --- | --- |
| 正常時（`normal`） | 実際の到着時刻が、そのままシステムに伝わる |
| 早い申告（`early`） | 対象船の到着時刻が、実際より早い時刻に変更される |
| 遅い申告（`late`） | 対象船の到着時刻が、実際より遅い時刻に変更される |

「船が実際に到着する時刻」と「システムに伝わる申告時刻」を分けることが、このプログラムの中心となる。
攻撃では申告時刻だけを変更し、実際の到着時刻と荷役時間は維持する。

初期設定では船10隻、バース3つ、攻撃対象V5、変更幅±4時間で、100回の比較を行う。
`simulation.py` は計算結果を表として返す。表示とCSV・JSON・グラフの保存は [main.py](../main.py) が担当する。

## 2. 全体の処理の流れ

```text
呼び出し元（main.pyなど）が run_experiment() を呼ぶ
    ↓
run_experiment()：設定を検証し、試行ごとに以下を繰り返す
    ├─ generate_ship_data()：元の船舶データを生成
    ├─ assign_berths()：正常時の比較基準を作成
    └─ 正常・早い申告・遅い申告の3条件を処理
         ├─ apply_attack()：条件に応じて申告時刻を設定
         ├─ assign_berths()：割当計画を作り、実際の荷役を計算
         ├─ 船ごとの正常時との差を計算
         └─ calculate_metrics()：評価指標を計算
    ↓
summarize_results()：全試行を集計
    ↓
元データ、スケジュール、評価指標、集計表、比較表を返す
```

ファイルには計算用の6つの関数が定義されている。
ファイル保存、グラフ作成、画面表示、コマンド引数の読み取りは行わない。
直接実行時に関数を呼ぶ処理もなく、実験は呼び出し元から開始する。

## 3. 使用するライブラリ

| ライブラリ | この実装での用途 |
| --- | --- |
| `numpy`（`np`） | 乱数生成、累積和、バースの利用可能時刻を扱う |
| `pandas`（`pd`） | 船舶データを表として扱い、並べ替え、集計、表の結合を行う |

Pandasの `DataFrame` は、行と列からなる表である。
例えば、元データでは1行が1隻の船、列が船番号・到着時刻・荷役時間を表す。
出力用のライブラリは `main.py` で読み込む。

## 4. ファイル先頭の設定値

| 設定名 | 初期値 | 意味 |
| --- | ---: | --- |
| `MEAN_INTERARRIVAL_TIME` | 2.37 | 船が到着する間隔の平均。単位は時間 |
| `HANDLING_SHAPE` | 2 | 基準荷役時間のガンマ分布の形状パラメータ |
| `HANDLING_SCALE` | 2.4 | 基準荷役時間のガンマ分布の尺度パラメータ |

`SCENARIOS` は `normal`、`early`、`late` の条件名を並べたタプルである。
`METRICS` は集計する8つの評価指標名を並べたタプルである。
集計ではこの順番に処理する。日本語の表示名への対応づけは `main.py` に置いている。

船数や試行回数などは関数の引数で指定する。
コマンドから指定する場合は、`main.py` が引数を読み取ってこの関数へ渡す。
上記の到着間隔・分布パラメータは、現在の実装ではファイル先頭の定数で設定する。
すべての時刻・時間の単位は「時間」で、実際の日付や時計の時刻は扱わない。

## 5. generate_ship_data()：船舶データの生成

### 入力と戻り値

```python
generate_ship_data(num_ships=10, num_berths=3, seed=42)
```

`num_ships` は船数、`num_berths` はバース数、`seed` は乱数生成の初期値である。
戻り値は、船ごとの到着時刻と全バースの荷役時間を持つ `DataFrame` である。

seedは乱数の再現に使う。使用するライブラリ環境と設定が同じなら、同じseedから同じデータを生成できる。

### 到着時刻の生成

1. `np.random.default_rng(seed)` で乱数生成器を作る。
2. `rng.exponential()` で、平均2.37時間の指数分布から到着間隔を生成する。
3. `np.cumsum()` で到着間隔を順に足して、到着時刻に変換する。
4. 最初の値を全体から引き、最初の船の到着を時刻0にする。

例えば、生成した間隔が `[1, 2, 3]` なら、累積和は `[1, 3, 6]` になる。
最初の値1を引くと、到着時刻は `[0, 2, 5]` になる。
この処理により、最初に生成した間隔はシミュレーションの開始時刻の調整に使われる。

### 基準荷役時間とバース別荷役時間

`rng.gamma()` で、船ごとに基準荷役時間を1つ生成する。
形状が2のガンマ分布は2-Erlang分布であり、今回の平均は `2 × 2.4 = 4.8` 時間となる。

各バースの荷役時間は、共通の基準時間を使って求める。

```text
荷役時間 = 基準荷役時間 × バース係数
```

係数は、2バース以上なら `np.linspace(0.9, 1.1, num_berths)` で等間隔に作る。
3バースでは0.9、1.0、1.1、1バースの場合は1.0とする。
その組を `rng.permutation()` で船ごとにランダムに並べ替え、各バースへ配置する。3バースでは各船に速い・標準・遅い係数が1つずつあるが、対応するバースは船によって異なる。実港の相性を推定したものではない。
同じseedと設定では配置も再現できる。生成後は配置を変えず、正常時と攻撃時で同じ荷役時間を用いる。
noiseは生成・適用しない。船ごとの基準時間と係数のランダム配置だけで荷役時間の違いを表す。

例えば基準時間5時間、係数の配置がB1=1.1、B2=0.9、B3=1.0なら、B1は5.5時間、B2は4.5時間、B3は5時間になる。
別の船ではB1に0.9が配置される場合もある。
同じ船の基準時間を共有するため、荷役に時間がかかる船は他のバースでも比較的長くなる。

### 生成される列

| 列名 | 内容 |
| --- | --- |
| `ship` | V1、V2、…という船番号 |
| `actual_arrival_time` | 実際の到着時刻 |
| `reported_arrival_time` | 申告到着時刻。生成直後は実到着時刻と同じ |
| `base_handling_time` | 船ごとの基準荷役時間 |
| `berth_factor_B1`、`berth_factor_B2`、… | その船に対して各バースへ配置した係数 |
| `handling_time_B1`、`handling_time_B2`、… | 各バースで荷役する場合の所要時間 |

この関数では船舶データを生成するだけで、バースの割当はまだ行わない。

## 6. apply_attack()：対象船の申告時刻の変更

```python
apply_attack(data, target_ship, shift_hours)
```

元データ、対象船の番号、変更時間を受け取り、申告時刻を設定した新しい表を返す。

1. `data.copy(deep=True)` で元データをコピーする。
2. `ship == target_ship` で対象船の行を選ぶ。
3. 対象船の実到着時刻に `shift_hours` を加え、申告時刻として設定する。
4. `clip(lower=0)` で、申告時刻が負にならないようにする。

現在の比較実験では対象船をV5に固定しており、生成データにはV5が必ず1隻含まれるため、対象行の存在数チェックは行わない。

例えば実到着時刻10時間の船に対し、変更時間−4なら申告時刻は6時間、+4なら14時間となる。
実到着時刻2時間の船を4時間早める場合は、申告時刻を0にする。

変更は常に実到着時刻を基準とする。
実到着時刻、荷役時間、対象船以外の申告時刻、引数として受け取った元の表は変更しない。
変更時間0もこの関数で扱い、正常条件の申告時刻を設定する。

## 7. assign_berths()：割当計画と実際の荷役

```python
assign_berths(data)
```

船舶データを受け取り、各船の割当バース・計画時刻・実行時刻・待ち時間などを持つ表を返す。
関数内は「計画の作成」と「計画の実行」の2段階に分かれる。

### 7.1 申告時刻で割当計画を作る

最初に、`handling_time_B` で始まる列を取り出し、利用できるバースを把握する。
`planned_available` は、各バースが計画上いつ空くかを記録する配列で、初期値はすべて0である。

船舶データを申告時刻の早い順に並べ、1隻ずつ割り当てる。
これがFCFS（First Come, First Served）の処理である。
`kind="stable"` を指定するため、同時刻の船は入力の行順を保つ。
このプログラムが生成する元データでは、それは船番号順に対応する。

各船について、すべてのバースの候補時刻を計算する。

```text
計画開始時刻 = max(申告到着時刻, バースが計画上空く時刻)
計画完了時刻 = 計画開始時刻 + そのバースでの荷役時間
```

コードでは候補を次のタプルにして、`min(candidates)` で選ぶ。

```text
(計画開始時刻, 計画完了時刻, バースの配列番号, 荷役時間)
```

Pythonのタプルは先頭から順に比較されるため、次の優先順位になる。

1. 計画開始時刻が最も早いバース。
2. 開始時刻が同じなら、計画完了時刻が最も早いバース。
3. 両方同じなら、配列番号が小さいバース。

例えば開始5・完了15のバースと、開始7・完了9のバースでは、開始が早い前者を選ぶ。
開始時刻を優先する規則であり、完了時刻だけを最小にする選択ではない。
選んだバースの `planned_available` を完了時刻に更新し、結果を `plan` に追加する。

この段階で選択に使う到着情報は申告時刻だけである。
実到着時刻は結果に記録するが、バースや計画時刻の決定には使わない。

### 7.2 実到着時刻に合わせて計画を実行する

次に、各バースの実際の利用可能時刻を表す `actual_available` を0で初期化する。
計画で決まったバースと順番を維持し、各船の実際の開始時刻を求める。

```text
実荷役開始 = max(計画開始時刻, 実到着時刻, バースが実際に空く時刻)
実完了時刻 = 実荷役開始 + 荷役時間
待ち時間 = 実荷役開始 − 実到着時刻
在港時間 = 実完了時刻 − 実到着時刻
```

`actual_available` を実完了時刻に更新することで、同じバースの後続船が前の船の終了前に開始することを防ぐ。
実到着時刻も `max()` に含めるため、到着前には荷役できない。

早く申告した船が未到着でも、後続船を先に入れる再割当は行わない。
遅く申告した船が既に到着していても、計画開始より早くは荷役しない。
これは「申告時刻を信じて作った予約計画を固定して実行する」運用を表す。

### 7.3 早い申告の計算例

説明用に、船3隻・バース1つの例を考える。実験の初期設定とは別の小さな例である。
V1の実到着時刻を0、V2を2、V3を5時間とし、荷役時間は順に1、1、2時間とする。
正常時はそれぞれ時刻0、2、5から開始でき、待ち時間は全船0となる。

V3だけを4時間早く申告すると、申告順はV1、V3、V2になる。

| 処理順 | 船 | 実到着 | 申告到着 | 荷役時間 | 計画開始 | 実開始 | 待ち時間 |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | V1 | 0 | 0 | 1 | 0 | 0 | 0 |
| 2 | V3 | 5 | 1 | 2 | 1 | 5 | 0 |
| 3 | V2 | 2 | 2 | 1 | 3 | 7 | 5 |

V3は時刻1から開始する計画になるが、実際には時刻5まで来ない。
V3を待った後、その荷役が時刻7に終わるため、V2の実開始は時刻7となる。
この結果、時刻2に到着済みのV2に5時間の待ちが生じる。

### 7.4 戻り値の列

| 列名 | 内容 |
| --- | --- |
| `assignment_order` | 申告時刻順で処理した順番。1から始まる |
| `ship` | 船番号 |
| `actual_arrival_time` | 実到着時刻 |
| `reported_arrival_time` | 申告到着時刻 |
| `assigned_berth` | 割り当てたバース名 |
| `handling_time` | 選んだバースでの荷役時間 |
| `planned_start_time` | 計画した開始時刻 |
| `planned_completion_time` | 計画した完了時刻 |
| `start_time` | 実際の開始時刻 |
| `completion_time` | その船の実完了時刻 |
| `waiting_time` | 実到着から荷役開始までの時間 |
| `turnaround_time` | 実到着から荷役完了までの時間 |

ここでの在港時間は、モデル上の荷役完了までの時間を表す。
荷役後の離岸や出港にかかる時間は含めていない。

## 8. calculate_metrics()：1試行・1条件の評価

```python
calculate_metrics(schedule, target_ship)
```

割当・実行結果の表と対象船の番号から、8つの評価指標を辞書として返す。

| 指標 | 計算内容 |
| --- | --- |
| `total_waiting_time` | 全船の待ち時間を合計 |
| `average_waiting_time` | 全船の待ち時間を平均 |
| `max_waiting_time` | 全船の待ち時間の最大値 |
| `total_turnaround_time` | 全船の在港時間を合計 |
| `average_turnaround_time` | 全船の在港時間を平均 |
| `completion_time` | 各船の実完了時刻の最大値。全船の荷役が終わる時刻 |
| `target_waiting_time` | 対象船1隻の待ち時間 |
| `other_average_waiting_time` | 対象船を除いた船の待ち時間の平均 |

`target` は対象船の行だけが真になる条件で、`~target` はその逆、つまり対象船以外を選ぶ。
全体平均に加えて対象船と他の船を分け、攻撃の負担がどこに現れるかを見られるようにする。

船別の `completion_time` はその船の完了時刻だが、この関数の同名の指標は全船の完了時刻である。
また、総待ち時間は船ごとの時間の合計であり、全船が完了するまでの経過時間とは異なる。

## 9. summarize_results()：全試行の集計

```python
summarize_results(run_metrics)
```

各試行・各条件の評価指標をまとめた表を受け取り、`summary` と `paired_comparison` の2つの表を返す。

### 各条件の平均と標準偏差

条件ごとに8指標を取り出し、試行回数・平均・標本標準偏差を保存する。
例えば平均待ち時間なら、各試行で求めた「全船の平均待ち時間」を100回分平均する。
標準偏差は試行ごとの値のばらつきを表し、平均値の信頼区間ではない。

`std(ddof=1)` は、試行回数から1を引いた数を分母に使う標本標準偏差を求める指定である。
1試行では定義できないので値は `NaN` となり、CSVでは空欄になる。

### 同じ試行の正常時との差

正常時と攻撃時の表を `set_index("trial")` で試行番号に対応づけてから引き算する。

```text
差 = 同じ試行の攻撃時の指標 − 正常時の指標
```

差の平均・標本標準偏差・最小・最大を求め、差が増えた試行、減った試行、変わらない試行の回数も数える。
浮動小数点の計算誤差を考慮し、±`1e-9`時間以内は変化なしとする。
`1e-9` は0.000000001を表す。

正常時自身については平均・標準偏差だけを保存し、正常時との差の表は作らない。
したがって、指標が8個なら `summary` は3条件×8指標で24行、`paired_comparison` は2攻撃×8指標で16行になる。

## 10. run_experiment()：比較実験の取りまとめ

```python
run_experiment(trials=100, num_ships=10, num_berths=3,
               seed=42, target_ship="V5", shift_hours=4.0)
```

各関数を組み合わせ、指定した回数の比較実験を行う。
この関数は結果の表を返すところまでを担当し、ファイルの保存は行わない。

### 設定の確認

実験を始める前に、次の条件を確認する。

- 試行回数は1以上。
- 船数は2以上。対象船以外の平均も計算するため、最低2隻とする。
- バース数は1以上。
- seedは0以上。
- 対象船がV1〜指定した船数の範囲に存在する。
- 変更幅は0以上の有限値。負の値、`NaN`、無限大を拒否する。

設定が不正なら `ValueError` を発生させる。
変更幅は正の大きさとして受け取り、早い申告では内部で符号を負にする。

### 試行ごとの処理

1. `trial_seed = seed + trial - 1` で、その試行のseedを決める。
2. `generate_ship_data()` で元データを1回生成し、試行番号・seedを付けて保存用リストに追加する。
3. 正常時の割当を先に計算し、船番号を索引とする比較基準を作る。
4. 正常0時間、早い申告−変更幅、遅い申告+変更幅の3条件を順に処理する。
5. 各条件で `apply_attack()` と `assign_berths()` を実行する。
6. 船ごとの正常時との差を計算する。
7. 条件名などを付けたスケジュールと、`calculate_metrics()` の評価指標をリストに追加する。

正常条件も3条件のループ内で計算する。先に作った比較基準と同じデータを使うため、同じ結果になる。
条件ごとに到着時刻や荷役時間の乱数を作り直す処理はない。

### 船別の対応づけと追加列

改ざんによって行の順番が変わるため、行番号ではなく船番号で正常時の値を取り出す。
`map(normal[column])` は、各船に対応する正常時の値を並べる処理である。

| 追加列 | 内容 |
| --- | --- |
| `waiting_time_change` | その船の攻撃時の待ち時間 − 正常時の待ち時間 |
| `turnaround_time_change` | その船の攻撃時の在港時間 − 正常時の在港時間 |
| `is_target` | 対象船なら真、それ以外は偽 |
| `arrival_shift` | 申告時刻 − 実到着時刻。0への丸めを反映した実際の変更幅 |
| `trial` | 試行番号。1から始まる |
| `seed` | その試行で使用したseed |
| `scenario` | `normal`、`early`、`late` のいずれか |

### 全試行の結合と戻り値

最後に評価指標を表にし、`summarize_results()` で集計する。
元データとスケジュールは `pd.concat(..., ignore_index=True)` で縦に結合し、行の索引を振り直す。
試行番号や船番号は列として保持される。

戻り値は次の5つの表を持つ辞書である。

| キー | 内容 | 初期設定での行数 |
| --- | --- | ---: |
| `ship_data` | 全試行の元データ | 100試行×10隻＝1,000 |
| `schedules` | 全試行・全条件の船別スケジュール | 100試行×3条件×10隻＝3,000 |
| `run_metrics` | 各試行・条件の8指標 | 100試行×3条件＝300 |
| `summary` | 各条件・指標の平均と標準偏差 | 3条件×8指標＝24 |
| `paired_comparison` | 正常時との差の集計 | 2攻撃×8指標＝16 |

## 11. 呼び出し方と出力処理との関係

Pythonから計算だけを行う場合は、次のように呼ぶ。

```python
from simulation import run_experiment

results = run_experiment(trials=100)
summary = results["summary"]
schedules = results["schedules"]
```

この呼び出しだけでは `results/` フォルダやファイルは作成されず、グラフや画面表示も行われない。
結果をどう利用するかは呼び出し元で決める。
`test_simulation.py` も同様に計算関数を読み込み、小さな入力で確認する。

コマンドから実験し、結果を保存する場合は、リポジトリのルートで次を実行する。

```bash
python main.py
python main.py --trials 1 --output results_single
python -m unittest -v
```

`main.py` の `main()` が、このファイルの `run_experiment()` を呼んで計算結果を受け取る。
その後のCSV・設定JSON・グラフの保存と画面表示は、すべて `main.py` が行う。
詳しくは [実行・出力処理の実装説明](実験実行と出力の実装説明.md) を参照する。

## 12. この実装の前提

到着間隔、荷役時間、バース係数、攻撃幅は予備実験の仮定である。
個別船の実測値から推定したパラメータではない。
船型、バースの長さ・水深、クレーン数、潮位などの条件は含めていない。

また、割当後はバースと順番を固定し、未到着船の代わりに別の船を入れる再割当は行わない。
比較結果は、こうした条件を置いたモデルでの影響として解釈する。
実際の神戸港で同じ待ち時間が発生することや、すべての条件で攻撃が必ず悪化を起こすことを示すものではない。
