# 到着予定情報の改ざんに関する攻撃モデル

作成日：2026年10月7日。

現在の実装に合わせて整理した、卒論で使う攻撃モデルの案である。ユーザーの依頼により記録したものであり、再割当が実装済みであることを意味しない。

## 攻撃の定義

| 項目 | 定義案 |
| --- | --- |
| 攻撃目的 | 対象船以外の船の待ち時間を増やし、港湾運用を妨害する |
| 攻撃者が知る情報 | 対象船の到着予定時刻、船の識別子、割当が申告時刻順のFCFSで行われること |
| 攻撃者の能力 | 計画作成前に、1隻の到着予定時刻だけを書き換えられる |
| 改ざん内容 | 到着予定時刻を一定時間早める、または遅らせる |
| 変更しないもの | 実際の到着、荷役時間、他船の情報、バースの設備・能力 |
| 扱わないこと | システムへの侵入手法、運用途中の継続的な改ざん、複数船の同時攻撃 |

ここでの到着予定情報は、実装上の「申告到着時刻」に対応する。侵入経路は特定せず、その情報が書き換えられた後の運用への影響を模擬する。

## 改ざんの例と再割当との関係

本来10時に到着する予定の船について、システム上の予定だけを6時に変更する。船は実際には10時に到着する。この例では予定と実到着が一致しているが、攻撃者が将来の実到着を正確に知っていることは仮定しない。

固定計画では、その船のためにバースや順番を確保して待つ場合があり、後続船に遅れが広がる可能性がある。
再割当では、到着済みで荷役未開始の船を空きバースへ割り当て直し、元の計画とは別のバースへの変更も許す方針を採用した。荷役中の船は移動・中断しない。実到着順で待ち船を選び、想定荷役時間が最短の空きバースへ割り当て、計画より早い開始も許す。この方式は未実装であり、同順位の規則と残る確認事項は[今後の計画](今後の計画.md)に記録する。
申告時刻を過ぎても未到着なら、いつ来るかは不明として扱い、その船のために空きバースを確保して待ち続けない。実際に到着した時点で待ち船に加える。運用者が改ざんを見抜いたり、正しい予定時刻を復元したりすることは前提にしない。

## 攻撃者が知らない情報

- 全船の正確な実到着時刻。
- 全船の正確な荷役時間。
- 改ざんした後に発生する待ち時間。

研究者が比較のために持つ情報と、攻撃者が使える情報を区別する。シミュレーション内部には実到着や荷役時間があるが、攻撃者が結果を先読みして最悪の対象を選べるという想定にはしない。

## 実験での対象船と改ざん幅の位置づけ

現在の実装では、対象船と改ざん幅は研究者が設定する。
序盤・中盤・最後の船や複数の改ざん幅を比較する実験は、攻撃者の選択を最適化するものではなく、攻撃条件による影響の違いを調べるものと位置づける。
採用した主実験では、10隻のうち序盤V2・中盤V5・最後V10をそれぞれ指定して1隻だけ改ざんし、固定計画と再割当を各設定100試行から比較する。最初の改ざん幅は±4時間とし、対象船・改ざん隻数は毎回ランダムにしない。具体的な比較条件と試行の対応は[今後の計画](今後の計画.md)に記録する。対象船1隻のランダム選択は追加実験の候補とし、複数船への攻撃は現在の主実験に含めない。

攻撃目的との対応を見るため、対象船以外の平均待ち時間の正常時からの増加を確認する。全船の平均待ち時間と対象船自身の待ち時間も併記する。
遅い申告では対象船自身だけが大きく待つこともある。それも結果として報告し、すべての改ざんが攻撃目的を達成するとは仮定しない。
同じ時刻のずれなら通常の予測誤差と改ざんで計算結果は同じになるため、意図的な書換えという想定と評価方法を明示する。

## 卒論に記載する文章案

> 本研究では、攻撃者がバース割当計画の作成前に、特定の1隻の到着予定時刻を書き換えられる状況を想定する。攻撃目的は、対象船以外の船舶の待ち時間を増加させる運用妨害とする。攻撃者は対象船の到着予定時刻とFCFSによる割当方式を知る一方、将来の正確な実到着時刻や荷役時間は知らないものとする。実際の船舶到着や荷役時間は変更せず、予定時刻の改ざんによる影響と、再割当による軽減効果を評価する。

この文章は、今後予定する再割当の評価まで含めた研究の説明案である。現段階の実装と結果は[要件定義書](要件定義書.md)と[予備比較レポート](予備比較レポート.md)を参照する。
