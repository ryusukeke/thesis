# 到着予定情報の改ざんに関する攻撃モデル

作成日：2026年10月7日。

情報改ざん、運用前の計画更新、運用ルールを整理した、卒論で使う攻撃モデルの案である。週単位の生成と3ルールの比較は実装した。正常時が原則0になる具体的な条件や、距離係数などは今後決める。

## 攻撃の定義

| 項目 | 定義案 |
| --- | --- |
| 攻撃目的 | 対象船以外の船の待ち時間を増やし、港湾運用を妨害する |
| 攻撃者が知る情報 | 対象船の到着予定時刻、船の識別子、割当が申告時刻順のFCFSで行われること |
| 攻撃者の能力 | 運用開始前の計画更新に使われる、1隻の到着予定時刻だけを書き換えられる |
| 改ざん内容 | 到着予定時刻を一定時間早める、または遅らせる |
| 変更しないもの | 実際の到着、荷役時間、他船の情報、バースの設備・能力 |
| 扱わないこと | システムへの侵入手法、運用途中の継続的な改ざん、複数船の同時攻撃 |

ここでの到着予定情報は、実装上の「申告到着時刻」に対応する。侵入経路は特定せず、その情報が書き換えられた後の運用への影響を模擬する。

## 改ざんのタイミングと計画更新

1週間の運用について、正常な申告情報で作った基準計画を比較用に保存する。攻撃条件では、荷役運用を始める前に1隻の申告到着時刻を書き換え、更新された申告情報で全船のバース・荷役順・計画開始時刻を1回作り直す。対象船の変更が他船の割当へ及ぼす影響も含めて比較する。

運用者は改ざんを検知せず、申告情報の更新として受け入れるものとする。正常な基準計画は研究者の比較用であり、攻撃条件の運用者が正しい到着予定を復元するためには使わない。実到着時刻と荷役時間は変更しない。

運用開始後は、その条件の確定した計画に各運用ルールを適用する。「元の計画」は、正常条件では正常な基準計画、攻撃条件では改ざん後に更新した計画を指す。運用前の全船の計画更新と、運用中の到着状況に応じた調整を区別する。同じ攻撃条件のルール間では、更新した初期計画を共有する。

## 改ざんの例と運用ルールとの関係

本来10時に到着する予定の船について、システム上の予定だけを6時に変更する。船は実際には10時に到着する。この例では予定と実到着が一致しているが、攻撃者が将来の実到着を正確に知っていることは仮定しない。

固定計画では、その船のためにバースや順番を確保して待つ場合があり、後続船に遅れが広がる可能性がある。
バース変更も許す再割当ルールでは、到着済みで荷役未開始の船の中で、その条件の元の計画順を優先する。事前に分かっている荷役時間が最短の空きバースへ割り当て、計画より早い開始も許す。荷役中の船は移動・中断しない。
このルールでは、申告時刻を過ぎても未到着なら、いつ来るかは不明として扱い、その船のために空きバースを確保して待ち続けない。実際に到着した時点で待ち船に加える。固定計画や同じバース内で順番を調整するルールも比較候補とする。具体的な規則と残る確認事項は[今後の計画](今後の計画.md)に記録する。

## 攻撃者が知らない情報

- 全船の正確な実到着時刻。
- 全船の正確な荷役時間。
- 改ざんした後に発生する待ち時間。

研究者が比較のために持つ情報と、攻撃者が使える情報を区別する。シミュレーション内部には実到着や荷役時間があるが、攻撃者が結果を先読みして最悪の対象を選べるという想定にはしない。
運用者は、船とバースの組合せごとの正確な荷役時間を事前に知っている前提を採用した。計画・再割当と実際の荷役には同じ値を使い、荷役時間の見積り誤差は扱わない。この前提は攻撃者に荷役時間を知らせるものではなく、運用者が未来の正確な実到着時刻を知るものでもない。

## 実験での対象船と改ざん幅の位置づけ

現在の実験プログラムでは対象船をV5に固定し、改ざん幅をコマンド引数で指定できる。シミュレーションの関数自体は対象船を引数で受け取るが、ターミナルから対象船を変更する機能は設けていない。
序盤・中盤・最後の船や複数の改ざん幅を比較する実験は、攻撃者の選択を最適化するものではなく、攻撃条件による影響の違いを調べるものと位置づける。
今後の主実験は1週間を対象に隻数を増やし、正常時の待ち時間が原則0になる条件で、複数の運用ルールを各設定10試行から比較する。対象船は週内の序盤・中盤・終盤の到着順から選ぶ方針とし、各攻撃条件で改ざんするのは1隻とする。具体的な選び方は未決定であり、以前のV2・V5・V10をそのまま週内の代表とは扱わない。±4時間は最初の改ざん幅の候補として見直す。対象船・改ざん隻数を毎回ランダムにする比較や、複数船への攻撃は初期の主実験には含めない。詳細は[今後の計画](今後の計画.md)を参照する。

攻撃目的との対応を見るため、対象船以外の平均待ち時間の正常時からの増加を確認する。全船の平均待ち時間と対象船自身の待ち時間も併記する。
遅い申告では対象船自身だけが大きく待つこともある。それも結果として報告し、すべての改ざんが攻撃目的を達成するとは仮定しない。
同じ時刻のずれなら通常の予測誤差と改ざんで計算結果は同じになるため、意図的な書換えという想定と評価方法を明示する。

## 卒論に記載する文章案

研究全体は、既存のバース割当・再割当の考え方を限定した到着情報改ざんの攻撃モデルに適用し、被害と軽減の条件を評価するものと位置づける。詳しくは[今後の計画](今後の計画.md)の「研究の目的とゴール」を参照する。

> 本研究では、1週間のバース運用の開始前に、攻撃者が特定の1隻の到着予定時刻を書き換え、その情報で全船の計画が1回更新される状況を想定する。攻撃目的は、対象船以外の船舶の待ち時間を増加させる運用妨害とする。攻撃者は対象船の到着予定時刻とFCFSによる割当方式を知る一方、将来の正確な実到着時刻や荷役時間は知らないものとする。実際の船舶到着や荷役時間は変更せず、正常時の待ち時間が原則0となる条件を基準に、改ざんの影響と複数の運用ルールによる軽減効果・限界を評価する。
