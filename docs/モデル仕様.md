# TOS停止時の限定的手動運用モデル

本書は実装済みの計算規則を示す。目的・条件の理由は [研究設計](研究設計.md)、関数と手計算は [実装説明](実装説明.md)、保存値は [実験結果と考察](実験結果と考察.md)を参照する。

## 1. 対象と入力

離散型4バース（B1〜B4）、1バース同時1隻・1船同時1バース。船長・岸壁長・着岸位置・喫水と水深による利用制約は省く。KICTの4バース体制は規模の参考であり、実運用全体の再現ではない。

船iの入力はID、到着時刻 a_i、荷役時間 h_i。全バースで同じ h_i を使う。通常時の予定計画、到着申告の改ざん、到着誤差、クレーン・ヤード・トラックはモデルに入れない。

到着間隔は指数分布。平均間隔は保存済み参照値3.029126213592233時間を到着頻度倍率で割る。荷役時間はGamma（形状2・尺度2.4）、平均4.8時間。分布と荷役の数値は仮定であり、神戸港から推定した値ではない。0以上168時間未満に到着する全船を生成し、168時間を超えても全船の完了まで処理する。

到着乱数は試行seed、荷役乱数はseed+100000。10試行はseed42〜51。同じ試行・頻度の入力を全条件で共有する。

## 2. 観測と選船

到着・荷役完了・空きバースを即時に観測できる。到着済み船について荷役見積りを紙等で利用でき、見積りが実際の時間と等しいと仮定する。未来の船は選船関数へ渡さない。

表1 次船の選択

| 状態・方式 | 優先順位 |
| --- | --- |
| 停止なし・停止前・復旧後 | 到着が早い順（FIFO） |
| 手動FIFOの手動時間帯 | 到着が早い順 |
| 短い荷役優先の手動時間帯 | 荷役時間が短い順→到着が早い順 |

同順位は船ID順。生成IDはV0001等なので順序は明確。使うバースは空いている番号が小さい順。開始後の追出し・中断・移動は行わない。

FIFOも短時間優先も単純な運用ルールであり、最適化を解いていない。通常のFIFOも最適解ではない。

## 3. 停止と復旧

停止開始 u=48時間、停止時間 D=12・24・48時間、準備時間 s=2時間、手動同時上限 K=2隻を与える。準備時間と同時上限は全実験で固定する。復旧時刻 r=u+D は通常業務へ戻れる時刻を表す。

表2 状態と新規開始の条件

| 区間 | 復旧待ち | 手動FIFO・短い荷役優先 |
| --- | --- | --- |
| t<u | FIFO、同時4隻 | FIFO、同時4隻 |
| u≤t<r、準備未完了 | 新規開始なし | 新規開始なし |
| u+s≤t<r | 新規開始なし | 荷役中の総隻数がK未満なら新規開始 |
| r≤t | FIFO、同時4隻 | FIFO、同時4隻 |

Kは**既に荷役中の船も含めた同時使用数の上限**で、固定したバースだけを開く意味ではない。停止時・準備完了時に荷役中の船がKを超えていても継続する。総隻数がK未満になってから新規開始する。荷役時間をKに応じて伸ばすことはしない。

準備は停止時から開始し、未来の実復旧時刻を見て切替判断を変えない。s≥Dなら手動中の新規開始はなく復旧待ちと同じ実行になる。準備完了と復旧が同時なら復旧を優先する。D=0なら停止はない。s≥DやD=0等は計算関数の境界テストで確認する条件であり、保存する実験の比較条件には加えない。

手動記録の再入力や復旧時照合の追加遅延は置かない。rはサーバー起動時刻だけを意味しない。開始済み荷役は復旧後も同じ完了時刻まで続く。

## 4. イベントの処理順

シミュレータは到着・完了・停止開始・準備完了・復旧の時刻へ進む。同じ時刻のイベントはまとめ、次の順に処理する。

1. その時刻までの到着と荷役完了を観測する。
2. 停止・準備・手動・復旧後の状態と新規開始の同時上限を決める。
3. 到着済み未開始船から次船を選び、空きバースに入れる。
4. 船と空き能力が残る限り、同じ時刻の開始を繰り返す。
5. 次のイベントへ進む。

手動区間は半開区間 [u+s,r)。uでは既に新規開始の制限がかかり、rでは通常FIFOで開始できる。コンピュータで全状態を保持するのはシミュレータの内部処理であり、現場が未来の到着情報を知る設定ではない。

## 5. 評価指標

船別待ち w_i=開始_i−a_i、在港時間=完了_i−a_i。全船平均待ちは船別待ちの平均。最大待ちは各試行の最大値を取り、その10試行平均を条件別表へ載せる。全試行をまとめた最大とは異なる。

主比較は同一入力での「短い荷役優先−手動FIFO」の全船平均待ち。負なら短時間優先の待ちが小さい。停止なしとの差も同じ試行で計算する。短時間優先には順序変更の効果が含まれるため、停止なしとの差を無条件に停止だけの被害とは呼ばない。

長時間船は各試行の入力荷役が大きい上位25％（端数切上げ、同時間はID順）。この群を全方式で固定し、平均待ちとFIFOとの差を調べる。FIFOより待ちが増えた船数は、船IDを対応させた待ち差が10⁻⁹時間より大きい船を数える。人数の比較ではなく隻数であり、微小な悪化も数える。

停止中到着群は a_i∈[u,r) で固定する。群の平均待ちと、同じ船の停止なしでの平均待ちを記録する。群の全船開始までの復旧後時間は max(0,群の最終開始−r)、空群は0。空群の平均待ちは空欄。停止なし単独行はDがないので群指標を空欄にする。この群の解消は、港全体の回復・全船完了・システム復旧時間を示さない。

手動負担の代理指標は、手動中の新規開始隻数と延べバース稼働時間。後者は各船の [開始,完了) と [u+s,r) の重なりを合計する。準備完了後も続く停止前開始船の荷役を含む。人・時間や人件費ではない。

集計は各試行を同じ重みで平均し、標本SD（ddof=1）と平均待ちの対応差の増加・減少・不変回数を求める。1試行のみの場合SDは空欄。95％信頼区間や統計的有意差は報告しない。
