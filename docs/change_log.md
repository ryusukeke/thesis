# 実装の修正内容

作成日：2026年10月6日

## 1. 修正の目的

7月28日のゼミ報告で予定していた、9月後半までの「正常時と攻撃時の予備比較」を実施できるように、既存の `sample.py` を修正した。
船ごとの荷役時間に相関を持たせ、到着時刻の改ざんを2種類追加し、同じ船舶データで正常時と比較できるようにした。
処理は1つのPythonファイルにまとめ、関数と繰り返し処理を中心に構成した。

この文書は今回の変更内容を説明する。操作方法は [README](../README.md)、実験結果と考察は [予備比較レポート](preliminary_comparison.md) に記載している。

## 3. 修正した処理

### 3.1 荷役時間の生成

以前は、同じ船でもバースごとに別の乱数を使って荷役時間を決めていた。
そのため、あるバースでは長時間かかる船が、別のバースでは極端に短時間になる場合があった。

修正後は、まず船ごとに基準荷役時間を1つ生成し、その値を各バースで共有する。

```text
基準荷役時間 = Gamma(shape=2, scale=2.4) から生成
各バースの荷役時間 = 基準荷役時間 × バース係数 × (1 + 誤差)
```

3バースの場合、係数はB1が0.9、B2が1.0、B3が1.1とし、誤差は−0.05〜+0.05の一様乱数とした。
基準荷役時間の平均は4.8時間である。
基準時間を共有することで、荷役に時間がかかる船はどのバースでも比較的長くなる。

分布の形状2・尺度2.4は以前の設定を引き継いでいる。今回の主な変更は、乱数を船ごとの基準時間として共有する点である。
到着間隔の指数分布、平均2.37時間、最初の船の到着を時刻0にする処理も引き継いだ。

乱数は `np.random.seed()` から `np.random.default_rng(seed)` に変更し、試行ごとに生成器を作る。
乱数生成方式と荷役時間の生成順が変わるため、旧実装と同じseedを指定しても旧実装と同じデータにはならない。
新実装では、同じ設定とライブラリ環境で再実行した結果が一致することを確認した。

### 3.2 実到着時刻と申告時刻の分離

以前の入力列 `arrival_time_A` を、次の2列に分けた。

| 列名 | 意味 | 使用する場面 |
| --- | --- | --- |
| `actual_arrival_time` | 船が実際に到着する時刻 | 実行時の開始制約、待ち時間・在港時間の計算 |
| `reported_arrival_time` | システムに伝わる到着時刻 | 割当順と割当計画の作成 |

正常時は両方を同じ値にする。攻撃時は申告時刻だけを変更する。
元データをコピーしてから変更するため、実到着時刻、荷役時間、対象船以外の申告時刻は維持される。

### 3.3 到着時刻を改ざんする攻撃の追加

対象船1隻について、次の3条件を比較する。

| 条件名 | 処理 |
| --- | --- |
| `normal` | 申告時刻を変更しない |
| `early` | 対象船の申告時刻を指定時間だけ早める |
| `late` | 対象船の申告時刻を指定時間だけ遅らせる |

初期設定の対象船はV5、変更幅は4時間である。
早めた時刻が0未満になる場合は0に丸める。
実際に変更した幅は `arrival_shift` に記録するため、丸めた場合も確認できる。

### 3.4 割当計画と実際の荷役の分離

FCFSの「開始時刻が早いバースを選び、同じ場合は完了時刻、バース番号で決める」という選択規則は維持した。
改ざんによって順序が変わるため、割当前に申告時刻で並べ替える処理を追加した。
同じ申告時刻なら元データの順番を保つ。

割当計画は申告時刻だけで作り、計画後はバースと各バース内の順番を固定する。
実行時の時刻は次の式で求める。

```text
実荷役開始 = max(計画開始時刻, 実到着時刻, そのバースの直前の船の実完了時刻)
実完了時刻 = 実荷役開始 + 荷役時間
待ち時間 = 実荷役開始 − 実到着時刻
在港時間 = 実完了時刻 − 実到着時刻
```

これにより、早く申告しても実際の到着前には荷役できず、同じバースで荷役が重ならない。
計画開始・完了時刻も保存するので、計画と実行のずれを追跡できる。

このモデルでは、予定の船が未到着でも、後続船を先に入れる再割当は行わない。
予約した船を待つことで後続船が遅れる運用を仮定している。

### 3.5 複数回実行と正常時との比較

初期設定では100試行を行い、seedを42から141まで1ずつ変える。
各試行で元の船舶データを1回生成し、正常・早い申告・遅い申告の3条件で共有する。
条件ごとに新しくデータを生成しないため、データの違いが攻撃の影響に混ざることを避けられる。

船別の差は船番号で対応づけ、集計指標の差は試行番号で対応づける。
改ざん後に行の順番が変わっても、別の船同士を比較しない。

```text
正常時との差 = 攻撃時の値 − 正常時の値
```

待ち時間などでは正の値が悪化、負の値が改善を意味する。
各条件の平均・標本標準偏差と、対応する試行の差の平均・標本標準偏差・最小・最大を集計する。
増加・減少・変化なしの回数も記録する。差が±0.000000001時間以内なら変化なしとする。
1試行では標本標準偏差を計算できないため、CSVの該当欄は空欄とする。

### 3.6 保存機能と設定変更

CSV5個、設定JSON、平均待ち時間の比較グラフを保存する機能を追加した。
CSVはExcelで開きやすいUTF-8 BOM付きとし、時刻・時間の単位を時間に統一した。
グラフは、全船と対象船以外の平均待ち時間をそれぞれ比較する。

`--trials`、`--ships`、`--berths`、`--seed`、`--attack-ship`、`--shift`、`--output`、`--no-plot` を追加した。
試行回数や船数が範囲外、対象船が存在しない、変更幅が負や非有限の場合はエラーを表示する。

同じ保存先では同名の結果を上書きする。
古いグラフが新しいCSVと混在しないよう、再実行時に古いグラフを削除してから作成する。
`--no-plot` の場合やMatplotlibが未導入の場合はCSVを保存し、グラフは作成しない。

## 5. 検証結果

実装時に次の内容を確認した。

- 小さな手計算例と割当・待ち時間・在港時間が一致する。
- 攻撃が元データや対象船以外の申告時刻を変更しない。
- 改ざん後の申告時刻に応じて割当順が変わる。
- 計画の作成に実到着時刻を使わない。
- 実到着前に荷役せず、同じバースの荷役が重ならない。
- 同じseedで生成した船舶データが一致する。
- 改ざん幅0では正常時と結果が一致する。
- 自動テスト10件がすべて成功する。
- 1試行・1バース・改ざん幅0でも、CSVとグラフを出力できる。
- 不正なコマンド引数を拒否し、グラフを無効にした場合に古いグラフを除去する。
- 保存したCSV5個が同じ設定で再計算した結果と一致する。
- 100試行×3条件の全300スケジュールで、実到着前の荷役や同一バースの重複がない。

予備比較の初期設定は、船10隻、バース3つ、対象V5、申告時刻の変更幅±4時間、100試行である。

| 条件 | 全船の平均待ち時間 | 正常時からの平均差 |
| --- | ---: | ---: |
| 正常時 | 0.406時間 | 0.000時間 |
| 4時間早く申告 | 0.704時間 | +0.298時間 |
| 4時間遅く申告 | 0.816時間 | +0.410時間 |

上記は保存済みの実験結果を小数点以下3桁で表示したもの。詳細は [予備比較レポート](preliminary_comparison.md) を参照する。

## 6. 実装範囲と前提

荷役時間の生成修正、正常時の繰り返し実行、到着時刻の改ざん2種類、正常時との予備比較まで実施した。
神戸港の公開統計の確認内容は [READMEの資料と仮定の説明](../README.md#神戸港の公開資料と仮定の区別) に記録している。

到着間隔や荷役時間のパラメータ、バース係数、攻撃幅は予備実験用の仮定であり、個別船の実測データから推定したものではない。
また、バースと順番を固定する運用を仮定しているため、随時再割当する実港の運用では影響が変わる可能性がある。
今回の結果はこのモデルの条件下での比較として扱う。
