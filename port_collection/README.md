# 神戸港EDIの収集・同期

このフォルダには、神戸港EDIのCSV取得、クラウドからの同期、重複整理、Excel作成をまとめています。
以下のコマンドは研究フォルダ`thesis/`を作業場所として実行します。
CSV・Excelの保存先は`data/kobe_port/`です。実行手順に続けて、保存・重複整理の規則と過去の確認記録を載せています。

[神戸港EDI](https://edi.port.city.kobe.jp/)の入港船予定表・出港船表・在港船表・移動船表を基本資料、航路通航船情報（中央）を補助資料として毎朝7時（日本時間）にクラウドで収集します。GitHub ActionsがSecretsを使ってログインし、非公開リポジトリへCSV原本を保存します。Macの電源が切れていても収集できます。

Mac側は毎朝8時のCodex定期実行で保存済みCSVを同期し、`data/kobe_port/船舶動静_蓄積.xlsx`を更新します。この同期にはMac・ネット接続・Codexアプリの起動が必要です。Macを数日使わなかった場合も、後で同期すれば保存されたCSVをまとめて取り込めます。2026年10月24日にスケジュールによるクラウド収集とExcel同期を確認しました。ただし、7時予定のクラウド実行は9時7分に開始し、Macの同期記録は10時2分でした。定刻どおりの実行は確認できていません。

神戸西・六甲東の「工事中」表示も、ログイン後のホームで毎朝確認します。表示がなくなり、表とCSVを正常に取得できた航路から自動追加します。初めて取得した時点でExcelのシートが増えます。ログイン前にメニューが見えないことは、工事完了とみなしません。

## 収集対象とデータの意味

| 表 | 用途 | ページ |
| --- | --- | --- |
| 入港船予定表 | 入港予定、船席、船の大きさなどを蓄積する | `/WW01020101` |
| 出港船表 | 出港として掲載された時刻・次港を蓄積する | `/WW01020104` |
| 在港船表 | 取得時点で在港として掲載されている船を記録する | `/WW01020102` |
| 移動船表 | 港内の移動前・移動後の船席を確認する | `/WW01020103` |
| 航路通航船情報（中央） | 入港・出港航路IN日時、離岸時刻などを補足する | `/WW01020201?data=04` |

神戸西は`/WW01020201?data=01`、六甲東は`/WW01020201?data=06`です。

各ページには未来の日時も含まれます。表に書かれた日時を、そのまま実際の到着・出港・荷役時刻とは扱いません。今回の収集データは補足資料として蓄積し、シミュレーションの入力にはまだ接続しません。工事中の航路は、表示の消失だけでなく、表名・見出しとCSVを確認して追加します。一度取得した航路のデータは、後日工事中や取得失敗になっても残します。

## Macで手動収集する場合

このPCにインストール済みのGoogle Chromeを、収集専用の一時プロファイルで使います。普段のChromeのログイン状態には依存しません。追加ライブラリは`port_collection/requirements.txt`にまとめています。

```bash
.venv/bin/python -m pip install -r port_collection/requirements.txt
```

研究フォルダの`.env`は、本人だけが読み書きできる権限`600`で作成済みです。次の2項目の引用符内に、自分で値を入力してください。他のサービスと使い回していないパスワードを選んでください。値をチャットに貼る必要はありません。

```dotenv
KOBE_EDI_ID=''
KOBE_EDI_PASSWORD=''
```

`.env`は平文です。Gitの対象外にしており、プログラムでも読み込み前に権限`600`を設定します。`.env.example`は空の記入例です。パスワードに単一引用符が含まれる場合の書き方などは[python-dotenvの形式説明](https://bbc2.github.io/python-dotenv/#file-format)を参照してください。

```bash
# ログイン、CSV取得、工事中の確認、Excel更新をまとめて実行
.venv/bin/python port_collection/collect_port_data.py

# 別の保存先を使う場合
.venv/bin/python port_collection/collect_port_data.py --output /tmp/kobe_port_collection
```

ローカルではID・パスワードを`.env`から読み込みます。クラウドでは`--credentials env`を指定し、GitHub Secretsを収集ステップだけの環境変数として受け取り、読み込み後は環境変数から取り除きます。どちらも値・ブラウザ画面・詳細な操作ログは保存しません。取得結果は`data/kobe_port/last_collection.json`に記録します。

| 引数 | 初期値 | 意味 |
| --- | --- | --- |
| `--output` | `data/kobe_port` | CSV原本・実行記録・Excelの保存先 |
| `--csv-only` | 指定なし | Excel作成を省略。クラウドでは指定する |
| `--credentials` | `file` | `file`は.env、`env`はクラウドのSecrets |
| `--browser` | `chrome` | MacではChrome、クラウドでは`chromium` |

未入力やログイン失敗の場合は停止し、既存のExcelを残します。全件成功時の終了コードは`0`、一部失敗または停止時は`1`です。一部の表だけ取得できた場合は、そのCSVを原本として保存し、取得できた分をExcelへ反映します。画像認証や追加認証などが必要になった場合は、自動ログインの対応を見直します。

## クラウドでの毎朝の収集

配置先は非公開リポジトリ[ryusuke2003/kobe-port-collector](https://github.com/ryusuke2003/kobe-port-collector)です。利用者の許可を受け、コードを配置し、`KOBE_EDI_ID`と`KOBE_EDI_PASSWORD`をGitHub Secretsに登録しました。[初回実行](https://github.com/ryusuke2003/kobe-port-collector/actions/runs/39946035708)で5表の取得と保存が成功しました。移行時には以前の13CSVも追加し、原本18ファイルから蓄積を始めました。日々の原本数は同期記録で確認できます。

クラウドで稼働する設定は、専用リポジトリの既定ブランチの`.github/workflows/collect-kobe-port.yml`にあります。このフォルダの[collect-kobe-port.yml](collect-kobe-port.yml)は、この研究フォルダの配置に合わせた設定の控えです。認証情報を変更する場合は、GitHubの「Settings → Secrets and variables → Actions」で2つのSecretsを更新します。Macの`.env`を書き換えても、GitHub Secretsは自動更新されません。`.env`自体はアップロードしていません。

- 毎日7時（日本時間、UTCの22時）に起動します。時刻ちょうどの実行は保証されず、混雑で遅延・実行の取りこぼしが起こる場合があります。手動実行も可能です。[GitHub公式のスケジュール説明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)
- CSV収集だけを実行し、Excelはクラウドで作りません。必要なライブラリは`port_collection/requirements.txt`、ブラウザはPlaywright付属Chromiumです。実行環境は初回に使ったUbuntu 24.04に固定しています。
- CSV原本と`last_collection.json`を、同じ非公開リポジトリの`codex/kobe-port-data`ブランチへ毎回自動コミットします。コードのブランチには取得データを追加しません。データの保存に有効期限のあるArtifactsは使いません。
- 一部の取得に失敗しても取得済みの原本と失敗記録は保存します。通信や保存に失敗した場合はGitHub Actionsの実行結果が失敗になります。リポジトリに書き込み権限が必要です。
- 公開リポジトリでは収集前に停止します。認証情報と収集データを見られる範囲は、それぞれGitHub Secretsとリポジトリの権限設定によります。

Mac側の定期実行（ID：`edi`）は「神戸港CSVをExcelへ同期」に変更し、毎日8時に設定しました。クラウドで7時に取得した後に同期するための時刻です。Mac側からの毎朝のEDI収集は、この同期処理へ置き換えています。

所有者アカウントはGitHub Freeで、Actionsの無料枠は月2,000分です。2026年10月23日に、支払い方法の未登録、Actionsの追加支出予算0ドルと予算到達時の停止設定を確認しました。課金設定の変更は行っていません。無料枠を使い切った場合は処理が停止します。他のリポジトリの利用量も合算されます。初回の実行時間は全体で約1分20秒でした。収集にOpenAI APIは使わず、APIキーは不要です。[GitHubの料金説明](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

## クラウドのCSVをMacのExcelに反映する

Macに保存済みのGitHub用HTTPS認証を使います。このMacから専用リポジトリへの読み取りとExcel更新を確認済みです。同期先のアクセス権が変わった場合は、GitHub用の認証設定も確認してください。

```bash
.venv/bin/python port_collection/sync_port_cloud.py --repository ryusuke2003/kobe-port-collector

# 別の保存先にCSVだけを取り込む場合
.venv/bin/python port_collection/sync_port_cloud.py --repository ryusuke2003/kobe-port-collector \
  --csv-only --output /tmp/kobe_port_cloud
```

`--repository`は必須、`--output`の初期値は`data/kobe_port`です。`--csv-only`を省略すると、既存の原本と取り込んだCSVからExcelを更新します。Macを数日停止していても、データ用ブランチに残っているCSVをまとめて取得できます。同名・同内容のファイルは追加せず、異なる内容なら上書きせず停止します。ローカルにしかない原本も残します。

`cloud_collection.json`はクラウド側の直近の収集結果、`last_cloud_sync.json`はMac側の同期日時・追加CSV数・Excel更新の成否です。同期に神戸港EDIのID・パスワードは使いません。取得したコードは実行せず、原本を検証してから追加します。Excel作成に失敗した場合も、既存の原本と完成済みExcelを残します。原本からの行の重複整理は従来と同じです。

## 手動で取得したCSVの追加

CSVを手動で取得した場合も、次のように追加できます。CSVの出力名は変更しないでください。

```bash
# 今回取得したCSVを指定する（ファイル名は例）
.venv/bin/python port_collection/import_port_csv.py \
  /Users/ryusuke/Downloads/2026102315411044_入港船予定表.csv \
  /Users/ryusuke/Downloads/2026102315420343_出港船表.csv \
  /Users/ryusuke/Downloads/2026102315413161_在港船表.csv \
  /Users/ryusuke/Downloads/2026102315415141_移動船表.csv

# 航路のCSVも同じ方法で追加できる
.venv/bin/python port_collection/import_port_csv.py \
  '/Users/ryusuke/Downloads/2026102315121601_航路通航船情報（中央）.csv'

# 保存済みの原本からExcelだけを再作成する
.venv/bin/python port_collection/import_port_csv.py
```

`port_collection/import_port_csv.py`の引数：

| 引数 | 初期値 | 意味 |
| --- | --- | --- |
| `csv` | 省略可 | 今回追加するCSVのパス。複数指定可 |
| `--output` | `data/kobe_port` | CSV原本とExcelの保存先 |
| `--preview-dir` | なし | 指定時は各シートの先頭部分のPNGも保存 |

原本は`raw/日付/`に残します。同じ表で全列が一致する行はまとめ、変更された行は履歴として保持します。初回・最終確認日時と確認CSV数を記録します。同じファイルを再度指定しても件数は増えません。

Excelは原本から再作成するため、手入力のメモは別ファイルに保存してください。取得した日時を実際の荷役時刻とみなすことはせず、収集処理からシミュレーションを自動実行することはありません。研究用集計は以下の別コマンドで行います。重複整理の詳細とデータの制約は、以下を参照してください。

## 保存と重複の扱い

保存先は `data/kobe_port/`。

- `船舶動静_蓄積.xlsx`：取得履歴、基本4表、中央。神戸西・六甲東は最初の取得時にシートを追加する。表にはフィルターと見出しの固定を設定する。
- `raw/YYYY-MM-DD/`：ダウンロードしたCSV原本。ファイル名を変更せず、日ごとに保存する。
- `last_collection.json`：直近の実行日時、取得行数、工事中などの見送り、失敗、Excel更新の成否。認証情報は含めない。

同じ表の**全列が一致する行**を1行にまとめ、初回確認日時・最終確認日時・確認CSV数・初回CSV・最終CSVを付ける。同じCSV内の同一行は1回の確認と数える。同じファイルを再取り込みしても増えない。

船名やコールサインだけでは重複を判定しない。同じ船でも、再寄港や港内移動がある。時刻・船席・記号などが異なる行は別の履歴として残す。表をまたいだ行の削除や、変更前の行の削除はしない。Excelの蓄積件数は、現在の船数やサイトの最新表示件数とは異なる。

CSVに年のない日時は、Excelでも原文の文字列で保持する。年の違う同じ月日の行を誤ってまとめないよう、**重複判定に使う年だけ**CSV出力日に最も近い年で補う。これは取得日の前後1年の候補から選ぶ仮定であり、実績年の確定ではない。

日時・記号の原文は原本CSVに保存する。空欄の見出しは、Excelでは「原文列2（見出しなし）」など列位置を示す名前にする。記号の意味は推測しない。総トン数・全長・喫水は数値として保存し、コールサインは先頭の0を含めて保持する。

Excelは原本から毎回作り直す。Excelに手入力したメモは更新時に引き継がれないため、分析やメモは別ファイルで行う。コードのブランチでは日々の取得データをGitの追跡対象から外す。クラウドでは保管のため、**非公開のデータ専用ブランチだけにCSV原本と収集結果を自動コミットする**。原本とExcelは必要に応じて別途バックアップする。

## 取得処理と認証の扱い

クラウドの定期収集と、Macで手動収集する場合は、収集プログラムを実行する。プログラムは次の順に処理する。

1. ローカルでは`.env`の所有者・権限を確認し、権限を`600`にしてID・パスワードを読み込む。クラウドではSecretsから受け取り、読み込み後は環境変数から取り除く。
2. 収集専用の一時プロファイルでブラウザ（MacはChrome、クラウドはChromium）を起動し、確認済みのHTTPSログイン画面に入力する。ログアウトのリンクが表示されることを確認する。
3. ログイン後のホームで「神戸西」「六甲東」の工事中表示を確認し、取得可能になったものを追加する。
4. 各表を開き、「更新」を押して「Download（CSV形式）」からCSVを取得する。表名・CSVの見出し・列数を確認して原本を保存する。
5. ローカルでは保存した原本を`port_collection/import_port_csv.py`でまとめ、Excelを更新する。クラウドでは`--csv-only`で省略し、CSV原本と収集結果をデータ用ブランチに保存する。
6. `last_collection.json`に表ごとの取得行数、見送り理由、失敗した処理、Excel更新の成否を記録する。

ブラウザのログイン状態は実行ごとに作り直す。ログイン失敗時は取得できたことにせず、同じ実行内で認証を繰り返さない。利用者が入力設定や認証方式を確認する。手動のCSV取得・取り込みも従来どおり利用できる。現在の自動取得は、確認済みのページ構成とCSVダウンロード操作を前提とする。サイトにページ送りや新しい絞り込み条件が追加された場合は、取得範囲を見直す。

ローカルは`dotenv_values(..., interpolate=False)`で値を直接読み、環境変数には展開しない。クラウドはGitHub Secretsを収集ステップだけの環境変数として受け取り、ブラウザ起動前に環境変数から取り除く。クラウドで`.env`を作らない。認証情報の入力直前に、ページとフォームの送信先が`https://edi.port.city.kobe.jp`であることを確認する。ブラウザのデバッグ出力を無効にし、ID・パスワード、例外の生の本文、画面、通信履歴、ログイン状態のファイルは保存しない。失敗の記録には、固定の処理名と表名だけを使う。

一部の表しか取得できなかった場合も、取得済みの有効なCSVは取り込める。未取得の表はその旨を報告し、前回の記録を残す。取り込みやExcel作成でエラーになった場合は、原本を残し、完成済みのExcelを置き換えない。

## プログラムの分担

この研究フォルダの収集用プログラムは`port_collection/`にまとめる。`ROOT`は研究フォルダ、`PROGRAM_DIR`は収集用プログラムのフォルダを表し、原本・Excelの保存先と`.env`の読み取り先は研究フォルダから決める。Python同士の呼び出しとExcel作成スクリプトの参照は`PROGRAM_DIR`から決める。

毎朝8時のMac向け定期実行も、新しい`port_collection/sync_port_cloud.py`を呼び出す。クラウドで稼働中の収集専用リポジトリは独立した配置で動いており、今回の研究フォルダ内の整理後も、毎朝のCSV収集は引き続きそのリポジトリで行う。

- `port_collection/collect_port_data.py`：認証情報の読み込み、自動ログイン、工事中表示の確認、CSV取得、ローカルではExcel更新の呼び出し。関数と繰り返しで処理する。
- `port_collection/collect-kobe-port.yml`：この研究フォルダの配置に合わせたクラウド実行設定の控え。稼働中の設定は専用リポジトリの`.github/workflows/collect-kobe-port.yml`にある。
- `port_collection/sync_port_cloud.py`：クラウドの原本の読み取り、ローカルへの追加、Excel更新の呼び出し。
- `port_collection/import_port_csv.py`：CSVの確認、原本保存、重複整理、Excel作成の呼び出し。
- `port_collection/build_port_workbook.mjs`：Codex付属の表計算ライブラリでExcelの表示を作る。

CSVの整理はPythonの標準ライブラリを中心に処理する。自動ログインとダウンロードにはPlaywright、ローカルの認証設定の読み取りにはpython-dotenvを使う。PlaywrightはMacではインストール済みのChrome、クラウドでは付属Chromiumを使い、一時的な収集用プロファイルを終了時に破棄する。Excel作成にはCodex付属のNode.jsを使うため、別のPCに移す場合は付属ランタイムの場所を確認する。実行手順はこのREADMEの前半を参照する。ブラウザ操作は[Playwrightのライブラリ説明](https://playwright.dev/python/docs/library)と[ダウンロードの説明](https://playwright.dev/python/docs/downloads)に基づく。

## 利用上の限界

毎朝1回の観測では、日中に掲載されて消えた船や予定変更を取り逃がす可能性がある。掲載が消えたことだけで出港・荷役終了を確定しない。荷役開始・終了、実際の待ち時間、船席ごとの同時利用可能数は、この収集だけでは確定できない。

クラウドの遅延や失敗で、当日分が8時の同期に間に合わない場合があります。Macのスリープ中の実行と未実行分の自動補完は未確認です。

## KICTの翌日予定を研究条件の参考にする

`analyze_port_data.py`は保存済み原本を読むだけで、ログイン・収集・Excel更新をしない。各日の最終取得の入港船予定表から、翌日・対象船席PC-14/PC-15(E)/PC-16/PC-17を抽出する。コールサイン（欠損時は船名）と予定日を同じスナップショット内でまとめ、取得履歴の行数を寄港数にしない。

```bash
.venv/bin/python port_collection/analyze_port_data.py --through 2026-11-04 --output results/kobe_reference_check
```

2026年11月5日の主実験では、13取得日の翌日予定103件から平均候補間隔を24×13/103時間とした。実績寄港数ではなく、予定日の変更で同一実寄港が別日の予報に現れる可能性や、同日複数寄港をまとめる限界がある。未取得日は0としない。分布形・荷役時間・実待ち時間は推定していない。

主実験の`main.py --study`も同じ関数を呼び、日別件数、対象行と原本の行番号、原本ハッシュ、基準間隔を研究結果フォルダへ保存する。毎朝の収集・同期や既存原本・Excelは変更しない。詳しくは[研究の要件](../docs/要件定義書.md)を参照する。
